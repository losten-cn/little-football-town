## 1. Accessibility Tier & Commitment

### 目标层级: WCAG-AA (Web Content Accessibility Guidelines 2.1 Level AA)

选择 AA 而非 AAA 的理由：本游戏为 PC 端像素风格管理模拟游戏，核心交互为鼠标驱动 UI + 键盘快捷键辅助。AA 层级在可操作性和视觉可读性上提供了合理的平衡，且不施加与像素艺术风格冲突的严苛对比度要求（AAA 要求 7:1 对比度）。

### 承诺范围

| 领域 | 承诺 | 理由 |
|------|------|------|
| 键盘完整可达 | **全部交互元素可通过键盘操作** | 鼠标用户占多数，但键盘备用路径保证无障碍底线 |
| 色彩独立传达 | **不单独依赖颜色传递信息** | 最常见障碍类型之一——色盲用户占比约 8% |
| 文字可读 | **最小字号 12px，核心文字对比度 ≥ 4.5:1** | WCAG-AA 基准；像素字体需要稍微放大补偿低分辨率 |
| 动效可控 | **所有动画提供 reduced-motion 替代** | 前庭障碍用户需求；管理 sim 本身动画量较少 |
| 屏幕阅读器就绪 | **关键信息元素提供语义标记** | Godot 4.5+ 内置 AccessKit 支持——低实现成本 |

### 不承诺的范围（MVP）

| 领域 | 状态 | 理由 |
|------|------|------|
| Gamepad 支持 | 不适用 | 管理模拟游戏不设计手柄交互 |
| 触屏支持 | 不适用 | PC-only 目标平台 |
| 语音控制 | 不覆盖 | 超出 MVP 范围 |
| 实时字幕 | 不适用 | 无实时语音/过场动画内容 |

## 2. General Principles

### 2.1 多重编码原则

任何传达游戏状态的信息必须使用至少两种感官/视觉通道，不单独依赖颜色：

| 信号类型 | 通道 1 | 通道 2 | 通道 3 (推荐) | 示例 |
|----------|--------|--------|--------------|------|
| 状态变化 | 颜色 | 图标 | 文字标签 | 伤病 = 红色 + 🔴 + 「伤病中」 |
| 数值增减 | 颜色 (绿/红) | 箭头 (↑/↓) | 数值差值 | `SPD 75 → 77 📈 +2.3` |
| 稀有度 | 颜色边框 | 星级 | 文字标签 | 传奇 = 金色边框 + ⭐⭐⭐ + 「传奇」 |
| 训练效率 | 颜色 (绿/黄) | 箭头 (↑/→/↓) | 文字等级 | 高效 = 绿色 + ↑ + 「高效」 |
| 匹配度 | 星级 | 数字 | — | ★★★★☆ + 匹配度 80% |
| 禁用态 | 50% 透明度 | 无点击响应 | `aria-disabled` 标记 | — |

### 2.2 操作确认原则

- **可逆操作**: 无需确认（切换标签、排序、切换球员、雷达悬停）
- **中等消耗操作**: Light Confirmation (#9) — 显示资源消耗摘要 + 确认/取消
- **不可逆操作**: Important Confirmation (#10) — 警告图标 + 详情 + 强制确认

### 2.3 信息反馈原则

- 每次操作必须有即时反馈（视觉 ≥ 100ms 内，无操作无响应超过 2 秒）
- 加载超过 500ms 必须显示骨架屏或进度指示器
- 错误状态必须解释原因 + 提供恢复路径（不只是"操作失败"）
- 空状态必须引导下一步操作（不只是"无数据"）

### 2.4 焦点管理原则

- 弹出覆盖层/对话框时，焦点自动移至覆盖层第一个可交互元素
- 关闭覆盖层时，焦点回到触发元素
- 屏幕切换后，焦点移至新屏幕第一个可交互元素（通常是返回按钮）
- Tab 焦点顺序必须从左到右、从上到下、与视觉布局一致

## 3. Keyboard Navigation

### 3.1 全局快捷键

所有界面统一响应的键盘快捷键（与 Pattern #13 对齐）：

| 快捷键 | 操作 | 作用域 |
|--------|------|--------|
| `ESC` | 返回上一级 / 关闭覆盖层 / 打开暂停菜单（L1） | 全局 |
| `Tab` | 聚焦下一个可交互元素 | 全局 |
| `Shift+Tab` | 聚焦上一个可交互元素 | 全局 |
| `Enter` | 激活当前聚焦元素 / 确认操作 | 全局 |
| `Space` | 切换 / 展开当前聚焦元素 | 全局 |
| `1-5` | 切换当前界面的标签/分类 | 有标签栏的界面 |
| `↑↓` | 列表行选择 / 数值调节 | 列表和可滚动区域 |
| `←→` | 水平导航 / 切换相邻条目 | 球员切换、标签切换 |
| `F1` | 打开帮助 / 提示面板 | 全局 |
| `F5` | 快速存档 | 全局 |
| `F9` | 快速读档 | 全局 |

### 3.2 导航约定

- **列表内**: `↑↓` 移动选择，`Enter` 确认进入；选择高亮必须有可见焦点环
- **覆盖层**: `ESC` 关闭；焦点陷入覆盖层内（不能 Tab 到覆盖层后面的元素）
- **确认对话框**: `Enter` 确认，`ESC` 取消；焦点默认在「取消」按钮上（防止误操作）
- **雷达图/图形组件**: 逐轴 `Tab` 访问，每轴显示 tooltip 精确值

### 3.3 焦点指示器

- 所有可交互元素在键盘聚焦时必须显示可见焦点环（2px 实线或发光边框）
- 焦点环颜色: `#FFD700` (金色) — 与像素艺术风格协调且对比度足够
- 禁用元素不在 Tab 顺序中
- 隐藏/不可见元素不在 Tab 顺序中

## 4. Visual Accessibility

### 4.1 文字与可读性

| 要求 | 标准 | 适用 |
|------|------|------|
| 最小字号 | 12px（像素字体等价） | 所有 UI 文字 |
| 正文对比度 | ≥ 4.5:1 (WCAG-AA) | 列表内容、属性值、描述文本 |
| 大文字对比度 | ≥ 3:1 | 标题、按钮文字（≥ 18px） |
| 行高 | ≥ 1.4× 字号 | 多行文本区域 |
| 字体回退 | 像素字体 → 系统等宽字体 | 本地化后非 CJK 文字 |

### 4.2 色彩无障碍

- **禁止单独依赖颜色传信**: 所有状态指示必须配合图标或文字（见 2.1 多重编码原则）
- **红/绿状态指示**: 必须以 `🔴`/`🟢` 图标或 +/- 符号作为颜色备份
- **通用安全调色板**:
  - 正面/增长: `#4CAF50` (绿) + `↑` 箭头
  - 负面/衰减: `#FF9800` (橙, 非红 — 避免红绿色盲混淆)
  - 警告: `#FFC107` (黄) + `⚠` 图标
  - 禁用/不可用: 50% 透明度
  - 稀有度边框: 无=灰, 良好=绿+1px, 稀有=蓝+2px, 传奇=金+3px + 粒子 → 配合星级和文字
- **色盲模拟测试**: 每个 UI 界面至少通过 Deutan (红绿色盲) 和 Protan (红色盲) 模拟验证

### 4.3 UI 缩放

- 支持 100% (默认) 和 125% 两档 UI 缩放
- 像素艺术资源在 125% 时使用 nearest-neighbor 缩放（保持像素清晰度）
- 布局在缩放后不得出现文字截断或元素重叠

## 5. Motion & Animation

### 5.1 Reduced-Motion 模式

当系统/游戏设置启用 reduced-motion 时，所有 UX spec 中定义的动画必须降级：

| 原动画 | Reduced-Motion 替代 | 时长 |
|--------|-------------------|------|
| 屏幕切换滑入/滑出 (#16) | 淡入/淡出 | 50ms |
| 属性值闪烁 (×3) | 静态高亮 | — |
| 粒子效果 (里程碑等) | 静态金色边框 | — |
| 面板滑入/滑出 | 淡入/淡出 | 50ms |
| 列表淡入 | 即时切换 | 0ms |
| 按钮缩放反馈 (#3, #4) | 亮度瞬时闪烁 | 50ms |

### 5.2 默认动画安全规则

- 不得使用快速频闪 (≥ 3 次/秒) — 可能诱发光敏性癫痫
- 视差效果不得超过 2 层 — 减轻前庭负担
- 屏幕震动/抖动效果：默认关闭，仅通过设置开启
- 所有循环动画（加载圈、空闲动画）在 reduced-motion 下必须停止

### 5.3 Reduced-Motion 开关

- 位置：`设置 → 辅助功能 → 减少动效`
- 默认：关闭（即正常动画）
- 首次启动时检测系统 `prefers-reduced-motion` 设置并询问是否启用

## 6. Screen Reader Support

Godot 4.5+ 内置 AccessKit 支持，提供了低实现成本的屏幕阅读器集成。

### 6.1 语义标记要求

| UI 元素 | 标记要求 | 示例 |
|---------|---------|------|
| 按钮 | 可操作 + 标签 + 当前状态 | `「开始训练」按钮 — 已选中基础体能训练` |
| 列表行 | 可选择 + 位置 + 内容摘要 | `第 3 项：梅西 — FW — 综合评分 88 — 训练效率 高效` |
| 状态徽章 | 状态描述 | `伤病中 — 恢复剩余 3 周` |
| 进度条 | 当前值 + 最大值 + 百分比 | `运动点数 180/200 — 90%` |
| 雷达图 | 逐轴读取 | `速度 75/80 — 潜力剩余 5；力量 62/75 — 潜力剩余 13` |
| 输入框 | 标签 + 当前值 | `搜索球员：已输入「梅」` |
| 标签页 | 选中/未选中 + 标签名 | `全部 — 已选中，12 名球员` |
| 对话框 | 对话框标题 + 内容摘要 | `确认训练 — 消耗 30 经费、5 运动点数、2 行动窗口` |

### 6.2 实时更新通知

- 训练结算完成后，自动播报：「训练完成 — 梅西速度从 75 提升到 77，增长 2.3 点」
- 资源变化时播报：「经费扣除 30，剩余 12,470」
- 错误状态播报：「训练失败 — 运动点数不足」
- 通知应为非侵入式（不中断当前操作），2 秒后自动消失

### 6.3 界面标题

- 每个屏幕必须有语义标题（`screen_title` 属性）
- 进入新屏幕时自动播报标题
- 标题命名规则：`功能名 — 上下文`，如 `训练中心 — 梅西`

## 7. Input Accessibility

### 7.1 点击目标尺寸

| 元素类型 | 最小尺寸 | 间距 |
|----------|---------|------|
| 按钮 | 36×24px | ≥ 4px |
| 列表行 | 全宽 × 28px | — |
| 图标按钮 | 24×24px (含 4px 内边距 = 32×32px 热区) | ≥ 4px |
| 标签页 | 60×28px | ≥ 2px |
| 关闭按钮 (×) | 24×24px 热区 | — |

### 7.2 拖拽替代方案

所有拖拽操作必须提供非拖拽替代路径：

| 拖拽操作 | 替代方案 |
|----------|---------|
| 建设模式拖放建筑 | 点击格子 → 选择建筑类型 → 确认放置 (点击-点击) |
| 球员阵容拖拽排序 | ↑↓ 键移动 + Enter 确认 |
| 地图平移拖拽 | WASD 键 / 方向键 / 边缘滚动 |

### 7.3 按键重复与长按

- 按键重复延迟：300ms 初始，50ms 间隔
- 不使用长按作为唯一触发方式——所有长按操作必须有替代（如右键菜单）
- 不设时间限制操作（不要求玩家在 N 秒内完成某操作）

### 7.4 输入重映射

- 所有全局快捷键（F1/F5/F9 除外）支持重映射
- 重映射界面：`设置 → 控制 → 键盘快捷键`
- MVP 阶段仅支持键盘重映射，不支持鼠标按键重映射

## 8. Per-Screen Checklist

每个界面 UX spec 在通过 `/ux-review` 时必须逐项验证：

| # | 检查项 | 来源 |
|---|--------|------|
| 1 | 所有可交互元素有可见焦点环（`#FFD700` 金色 2px） | §3.3 |
| 2 | Tab 焦点顺序从左到右、从上到下、与视觉布局一致 | §2.4 |
| 3 | `ESC` 正确返回上一级或关闭覆盖层 | §3.1 |
| 4 | 列表支持 `↑↓` 选择 + `Enter` 确认 | §3.2 |
| 5 | 覆盖层焦点陷入，关闭后焦点回到触发元素 | §3.2 |
| 6 | 状态信息使用至少两种通道（颜色 + 图标/文字） | §2.1 |
| 7 | 红/绿状态有图标或符号备份 | §4.2 |
| 8 | 正文对比度 ≥ 4.5:1，最小字号 ≥ 12px | §4.1 |
| 9 | 所有拖拽操作有非拖拽替代路径 | §7.2 |
| 10 | 所有动画有 reduced-motion 替代（50ms 淡入淡出或静态） | §5.1 |
| 11 | 无快速频闪 (≥ 3 次/秒) | §5.2 |
| 12 | 加载超过 500ms 有骨架屏或进度指示器 | §2.3 |
| 13 | 空状态有引导文案 + 下一步操作入口 | §2.3 |
| 14 | 错误状态有原因说明 + 恢复路径 | §2.3 |
| 15 | 按钮/列表行/图标按钮达到最小点击尺寸 | §7.1 |
| 16 | 关键 UI 元素有语义标记（screen_title + 按钮标签 + 列表内容摘要） | §6.1 |
| 17 | 实时状态变更触发阅读器通知（训练结算、资源变化、错误） | §6.2 |
| 18 | 无时间限制操作 | §7.3 |

**验证方式**: 每条目以「键盘 Tab 遍历 + 屏幕阅读器播报 + 色盲模拟截图」三项方式之一验证。

## 9. Testing & Verification

### 9.1 测试工具

| 工具 | 用途 | 阶段 |
|------|------|------|
| Godot 内置 AccessKit 调试面板 | 验证语义标记正确性 | 开发阶段 |
| Windows Narrator / Linux Orca | 端到端屏幕阅读器测试 | QA 阶段 |
| 色盲模拟滤镜 (Deutan/Protan) | 色彩无障碍验证 | 设计审查 + QA |
| 键盘 Tab 遍历 (手动) | 焦点顺序 + 焦点环可见性 | 每个界面 |
| Reduced-motion 开关测试 | 动画降级验证 | 每个界面 |

### 9.2 测试场景

| 场景 | 覆盖界面 | 验证重点 |
|------|---------|---------|
| 新档首次启动 → 完成引导 | 小镇主视图 + 弹窗 | 焦点管理 + 空状态引导 + 阅读器播报 |
| 完整训练流程 | 球员管理 → 球员详情 → 训练规划 → Growth Review | Tab 遍历 + 列表导航 + 实时通知 |
| 比赛流程 | 赛前 → 赛中 → 赛后结算 | 动态内容阅读器播报 + 色彩编码 |
| 建设操作 | 小镇主视图 + 建设模式 | 拖拽替代路径 + 焦点管理 |
| 存档/读档 | 暂停菜单 | 确认对话框焦点 + 加载状态 |

### 9.3 验收标准

- [ ] 18 项 Per-Screen Checklist 对全部 5 个 MVP 界面 100% 通过
- [ ] Deutan + Protan 色盲模拟下，所有界面无不依赖颜色即可完整操作
- [ ] Windows Narrator 可完整播报一次训练流程（从选择球员到查看成长结果）
- [ ] Reduced-motion 启用后，所有界面无动画时长 > 50ms
- [ ] 键盘 Tab 可到达每个界面的所有可交互元素，无焦点陷阱
