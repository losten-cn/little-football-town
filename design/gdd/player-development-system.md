## Overview

运动员培养系统是《足球小镇》中负责把“普通球员逐步成长为可靠主力、明星乃至传奇”的核心养成层。它围绕球员招募、训练安排、属性成长、状态变化、潜力兑现以及长期培养反馈展开，把数值系统定义的共享属性与成长规则，转化为玩家可持续投入、可比较、可规划的培养体验。它不直接决定比赛胜负、赛程推进或经济收支本身，而是为这些系统提供球队实力成长的主要来源，让玩家通过一次次训练、选择和长期投入，明确感受到自己的球队正在被亲手塑造。

## Player Fantasy

运动员培养系统服务的玩家幻想是：“我亲手把一名普通球员培养成了属于这座小镇的传奇。”玩家不只是看到数值上升，而是会逐渐对球员产生投入感：记住他最初的短板、见证他在训练和比赛后一点点变强、为了他的成长路线做出取舍，并最终在关键比赛中看到这些长期投入得到回报。

这种幻想的重点不是高压竞争下的极限养成，而是长期陪伴式成长中的成就感与归属感。玩家应该相信，每一次训练安排、每一次资源投入、每一次对年轻球员的坚持，都会在未来变成可见的成长痕迹。运动员培养系统必须让“培养一个人”这件事既有规划价值，又有情感重量，让球员不只是阵容里的数值单位，而是玩家愿意长期投入和期待回报的成长对象。

## Detailed Rules

### Core Rules

1. 运动员培养系统是球员长期成长的权威来源，负责定义球员如何被招募、训练、成长、进入状态变化并形成长期培养轨迹。
2. 本系统只拥有“培养逻辑”和“成长语义”，不拥有比赛胜负、赛程推进、全局资源来源或共享公式边界：
   - 五维属性、`current / potential / effective` 三层值语义由数值系统拥有；
   - 行动窗口、时间推进与关键节点由时间与赛季推进系统拥有；
   - 长期持久化边界由存档与读档系统拥有；
   - 高级技能效果与复杂特性内容由后续技能与特性系统扩展。
3. 每名球员必须至少拥有以下培养相关长期字段：基础身份信息、年龄（足球年龄，每赛季结束时 +1）、主位置/偏好位置、五维当前属性、潜力上限、训练效率、状态标签、培养历史摘要，以及可被比赛系统消费的成长结果。

> **年龄字段接口**: 年龄是本系统拥有的球员长期属性。小镇建设系统查询球员年龄以判定 `youth_training_bonus` 是否适用（默认阈值 ≤22 岁）。年龄在赛季结算时由时间与赛季推进系统触发推进，不由本系统独立递增。
4. 每名球员都必须具有独立的 `training_efficiency`（训练效率系数），用于体现同样训练投入下不同球员的实际成长差异。该值是培养系统内部的核心个体差异之一，不允许所有球员同质化成长。
5. 每名球员都必须具有明确的成长天花板。潜力上限本体引用数值系统的 `potential_cap`，但由本系统定义不同球员层级如何映射到不同潜力区间。
6. 本系统必须定义球员分层，用于支撑“普通球员、优秀球员、明星球员、传奇胚子”之间的培养差异。至少要体现三类差异：
   - 潜力区间不同；
   - 训练效率不同；
   - 单位成长投入的长期性价比不同。
7. 建议的 MVP 分层口径如下，后续可通过调参修订：
   - 普通球员：培养成本相对较低，训练反馈来得快，但潜力区间偏低，后期更早触顶；
   - 优秀球员：培养成本与成长速度较平衡，适合作为中期主力；
   - 明星球员：初始投入更高，短期性价比未必最好，但潜力区间更高，长期回报更强；
   - 传奇胚子：极少数高上限对象，培养周期更长、资源要求更高，但可以成为终局核心。
8. 本系统必须把“投入产出性价比”做成显性策略取舍，而不是隐藏数值：普通球员应更容易快速练成可用战力，高潜力球员则需要更长周期和更多资源才能兑现优势。
9. 单次训练必须同时声明三件事：训练目标、时间消耗、资源消耗。训练不得绕过时间系统的统一行动窗口，也不得绕过数值系统的共享成长递减规则。
10. 单次训练的实际收益必须建立在共享 `attribute_growth` 之上，再叠加本系统拥有的训练效率、训练项目匹配度、球员当前状态等修正来源。培养系统可以决定“谁练得更值”，但不能改写共享成长公式本体。
11. 训练必须是有方向的，而不是平均给所有属性灌值。每个训练项目至少应指定一个主成长属性，并可选择性带动少量副属性成长。
12. 球员状态必须影响培养结果，但这种影响应服务低压力体验，而不是制造高压惩罚。疲劳、心情、健康或比赛负荷可以降低训练收益或提高恢复需求，但不应轻易让玩家长期报废一个培养对象。
13. 本系统必须允许玩家基于球队阶段做不同培养选择，例如：
   - 先把普通球员练成稳定轮换，追求短期阵容成型；
   - 集中资源培养明星球员，追求中长期爆发；
   - 平衡培养多名优秀球员，追求稳健成长曲线。
14. 招募进入培养系统的球员，必须带着可读的成长画像进入：至少包括当前强弱项、潜力层级、训练效率倾向和预期培养定位。玩家不需要知道所有底层公式，但必须能理解“这个人为什么值得练”或“不值得重投”。
15. 球员达到不同成长阶段后，系统必须给出可见反馈，例如属性提升、定位变化、培养里程碑、训练效率变化提示或进入主力阵容的可能性提升。
16. 培养系统必须为比赛系统提供结构化输出，至少包括：球员当前属性、有效属性、状态标签、成长结果摘要和是否适合当前位置的培养倾向。
17. 培养结果必须被视为长期权威状态，在稳定节点落档；已确认的训练收益不得在读档后丢失，也不得因重复恢复而重复结算。
18. MVP 阶段的培养系统目标不是做复杂到难以理解的球员模拟，而是清晰验证“投入训练 → 看到成长 → 比赛反馈成长价值 → 再决定下一步培养”的核心闭环。

## Formulas

### 1. 状态修正后的训练效率

`fatigue_adjusted_training_efficiency` 的公式定义如下：

`fatigue_adjusted_training_efficiency = clamp(training_efficiency × condition_multiplier × morale_multiplier, 0.5, 1.8)`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 基础训练效率 | `training_efficiency` | float | 0.8–1.5 | 球员的长期个体成长效率，体现“同样训练谁练得更值” |
| 身体状态修正 | `condition_multiplier` | float | 0.6–1.1 | 由疲劳、健康、伤病恢复状态带来的训练效率修正 |
| 心态修正 | `morale_multiplier` | float | 0.9–1.1 | 由心情、自信、团队氛围等状态带来的训练效率修正 |
| 状态修正后的训练效率 | `fatigue_adjusted_training_efficiency` | float | 0.5–1.8 | 单次训练实际使用的有效训练效率 |

**Output Range:** 0.5–1.8；低于 0.5 时按 0.5 处理，高于 1.8 时按 1.8 处理。  
**Example:** 若某球员 `training_efficiency = 1.2`、`condition_multiplier = 0.9`、`morale_multiplier = 1.05`，则 `fatigue_adjusted_training_efficiency = clamp(1.2 × 0.9 × 1.05, 0.5, 1.8) = 1.134`。

### 2. 单次训练实际成长

`training_actual_gain` 的公式定义如下：

`training_actual_gain = min(potential_cap - current_attribute, attribute_growth(raw_growth_input, current_attribute, potential_cap, decay_factor) × fatigue_adjusted_training_efficiency × training_focus_match_multiplier × facility_training_multiplier)`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 未衰减成长值 | `raw_growth_input` | float | ≥ 0 | 某训练项目提供的基础成长输入 |
| 当前属性值 | `current_attribute` | int | 1–100 | 球员在目标属性上的当前永久值 |
| 潜力上限 | `potential_cap` | int | 1–100，且 ≥ `current_attribute` | 球员在该属性上的常规成长上限 |
| 衰减因子 | `decay_factor` | float | 0.8–1.8 | 继承数值系统的成长递减强度，默认 1.2。不得在本系统中覆盖范围 |
| 状态修正后的训练效率 | `fatigue_adjusted_training_efficiency` | float | 0.5–1.8 | 经过状态修正后的有效训练效率 |
| 训练匹配倍率 | `training_focus_match_multiplier` | float | 0.7–1.3 | 当前训练项目与球员定位、成长方向的匹配程度 |
| 设施训练倍率 | `facility_training_multiplier` | float | 1.0–1.75 | 由小镇建设系统组合提供的设施侧训练倍率（`training_efficiency_multiplier × youth_training_bonus × adj_tr_youth_multiplier`）。无设施时 = 1.0；MVP 最大值 = 1.725（训练场 Lv.5 × 青训营自身 Lv.5 × 邻接 Lv.5+5）。上限 1.75 保留取整余量供扩展 |
| 单次训练实际成长 | `training_actual_gain` | float | 0–(`potential_cap - current_attribute`) | 单次训练最终能落到目标属性上的实际成长量 |

**Output Range:** 0 到剩余可成长空间；当 `current_attribute = potential_cap` 时输出必须为 0。  
**Example:** 若 `raw_growth_input = 3.0`、`current_attribute = 50`、`potential_cap = 80`、`decay_factor = 1.2`、`fatigue_adjusted_training_efficiency = 1.1`、`training_focus_match_multiplier = 1.2`、`facility_training_multiplier = 1.15`，且共享 `attribute_growth(...) = 1.5`，则 `training_actual_gain = min(30, 1.5 × 1.1 × 1.2 × 1.15) = min(30, 2.277) = 2.277`。

### 3. 球员分层潜力区间映射

`player_tier_potential_band` 的公式定义如下：

`player_tier_potential_band = lookup(player_tier)`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 球员层级 | `player_tier` | enum | 普通 / 优秀 / 明星 / 传奇胚子 | 该球员所属的培养层级 |
| 潜力区间 | `player_tier_potential_band` | tuple[int, int] | [60, 100] | 该层级默认映射到的潜力上限区间 |

**Mapping Table:**

| Player tier | Potential band |
|---|---|
| 普通 | 60–75 |
| 优秀 | 70–85 |
| 明星 | 85–95 |
| 传奇胚子 | 92–100 |

**Output Range:** 60–100；这是培养系统拥有的“层级到潜力区间”的默认映射口径，具体单名球员的 `potential_cap` 必须落在其所属层级区间内。  
**Example:** 若某球员 `player_tier = 明星`，则 `player_tier_potential_band = [85, 95]`，该球员的默认潜力上限应从该区间内生成或分配。

### 4. 培养投入产出比

`player_development_roi` 的公式定义如下：

`player_development_roi = effective_growth_value / max(1, weighted_total_training_cost)`

**子公式 4a — 有效成长价值:**

`effective_growth_value = main_attribute_gain × 1.0 + secondary_attribute_gains_sum × 0.35`

主属性成长权重为 1.0，副属性成长权重之和以 0.35 系数折算。例如：一次训练主属性 SPD +2.0、副属性 PWR +0.5、STA +0.3，则 `effective_growth_value = 2.0×1.0 + (0.5+0.3)×0.35 = 2.0 + 0.28 = 2.28`。

**子公式 4b — 加权训练总成本:**

`weighted_total_training_cost = funds_cost + ap_cost × ap_to_funds_weight + time_cost_slots`

其中 `ap_to_funds_weight` 由经济管理系统定义（默认 50，即 1 AP ≈ 50 经费的决策权重。不得在本系统中覆盖；具体值以经济管理系统为准）。`time_cost_slots` 为占用的行动窗口数（每个窗口权重等价于约 5 经费的机会成本）。

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 主属性成长 | `main_attribute_gain` | float | ≥ 0 | 本次训练在主目标属性上的 `training_actual_gain` |
| 副属性成长合计 | `secondary_attribute_gains_sum` | float | ≥ 0 | 本次训练在所有副属性上的 `training_actual_gain` 之和 |
| 经费消耗 | `funds_cost` | float | ≥ 0 | 本次训练的经费成本（见训练消耗表） |
| 运动点数消耗 | `ap_cost` | float | ≥ 0 | 本次训练的运动点数成本（见训练消耗表） |
| AP 折算权重 | `ap_to_funds_weight` | float | 40–60 | 1 AP 等价于多少经费的决策权重，默认 50（由经济管理系统提供，不得在本系统中覆盖） |
| 时间窗口消耗 | `time_cost_slots` | float | 1–3 | 本次训练占用的行动窗口数，每个窗口折算约 5 经费机会成本 |
| 有效成长价值 | `effective_growth_value` | float | ≥ 0 | 加权汇总后的单次训练成长价值 |
| 加权训练总成本 | `weighted_total_training_cost` | float | ≥ 0 | 经费+AP+时间三维成本的统一加权值 |
| 培养投入产出比 | `player_development_roi` | float | 0–unbounded | 单次训练的综合性价比。越高 = 越"值" |

**Output Range:** ≥ 0。数值越高，该球员在当前阶段的培养性价比越高。

**Example:** 一次训练：主属性 SPD +2.0、副属性 PWR +0.5、STA +0.3；消耗经费 30、AP 5、时间 1 窗口。`effective_growth_value = 2.0 + 0.8×0.35 = 2.28`。`weighted_total_training_cost = 30 + 5×50 + 1×5 = 285`。`player_development_roi = 2.28 / 285 ≈ 0.0080`。同一项目训练明星球员（效率更高，同样消耗获得 +3.2 主属性 +1.0 副属性）：`effective_growth_value = 3.2 + 1.0×0.35 = 3.55`，`ROI = 3.55/285 ≈ 0.0125`——短期 ROI 明星更高（因效率高）。若普通球员训练消耗更低（经费 15、AP 3），则 `ROI = 2.28/(15 + 3×50 + 1×5) = 2.28/170 ≈ 0.0134`——普通球员短期反超。这正是 `short_term_roi_gap_target` 调参项控制的效果。

### 5. 训练消耗框架

单次训练的资源消耗由以下公式确定，具体数值在训练项目数据表中定义：

| 消耗项 | 符号 | 范围 | 描述 |
|--------|------|------|------|
| 经费 | `funds_cost` | 10–50 | 单次训练的经费消耗，由训练项目 tier 决定 |
| 运动点数 | `ap_cost` | 3–10 | 单次训练的 AP 消耗，由训练项目强度决定 |
| 行动窗口 | `time_cost_slots` | 1–3 | 单次训练占用时间系统的行动窗口数 |

> **训练项目数据表**: MVP 阶段提供最少 3 个训练项目以验证公式闭环（如：基础体能训练、技术训练、战术训练）。每个项目指定主属性、可带动的副属性、消耗值。具体项目清单见 `assets/data/training-items.csv`（MVP 最少 3 项，Alpha 扩展至 6-8 项）。本 GDD 不锁定训练项目内容——项目列表由数据表控制，培养系统只定义公式框架。

### Formula Ownership Notes

- `attribute_growth` 不在本系统中重新定义；本系统只在其基础上叠加训练效率、状态和训练匹配修正。
- `potential_cap` 的全局合法边界由数值系统拥有；本系统只定义不同球员层级如何映射到潜力区间。
- `weighted_total_training_cost` 的资源本体不在本系统中定义；经费、运动点数等资源口径由数值系统与经济系统共同约束。
- 如果后续比赛系统、技能系统或建设系统要改写训练效率上限、潜力区间映射或 ROI 口径，必须先回到本系统修订，而不能在下游 GDD 中静默覆盖。

## Edge Cases

- **If `training_efficiency < 0.8` or `training_efficiency > 1.5`**: 该球员训练效率配置视为异常；进入训练结算前必须先钳制回合法范围，并标记该球员培养数据需要复核。
- **If `fatigue_adjusted_training_efficiency` 被状态修正压到极低值**: 系统仍可允许训练发生，但必须保证玩家能清楚看到“本次训练收益显著降低”的原因；不得让训练看起来像无故失效。
- **If `current_attribute = potential_cap`**: 该属性的 `training_actual_gain` 必须为 `0`；系统不得继续消耗同类高价值培养资源却不给出任何可读反馈。
- **If 球员的 `potential_cap` 超出其所属层级默认区间**: 该球员应被视为特殊个体或异常配置；必须明确标记来源，而不能在常规层级规则里静默混用。
- **If 普通球员的短期 ROI 长期高于明星球员且没有触顶压力**: 这说明培养分层失衡；系统应视为调参失败，而不是把所有球员都做成同一路线最优。
- **If 明星球员前期投入极高但长期回报仍持续低于普通球员**: 该结果说明“高投入高上限”幻想没有成立；必须通过潜力区间、训练效率或资源成本重新校准。
- **If 训练项目与球员定位严重不匹配**: 系统应允许这种选择存在，但必须通过较低的 `training_focus_match_multiplier` 体现低效率，而不是让错误培养路线也同样高效。
- **If 球员处于高疲劳、低心情或恢复中状态**: 系统可以降低训练收益或提高状态风险，但不得直接把球员推入长期不可恢复的报废状态。
- **If 玩家连续多轮只培养同一名高潜力球员**: 系统应允许“集中培养”路线成立，但必须通过资源、时间窗口和其他球员停滞的机会成本体现取舍，而不是免费滚雪球。
- **If 玩家长期只培养普通球员，不投入高潜力对象**: 系统应允许这种低风险路线在前中期成立，但后期必须因潜力天花板而逐渐暴露上限。
- **If 玩家只培养明星球员而忽略普通轮换球员**: 系统应允许“赌核心”路线，但阵容稳定性、比赛覆盖面或资源压力应逐步显现短板。
- **If 一次训练同时让多个属性成长**: 主属性收益必须明显高于副属性；不得因为多属性溢出让一次训练同时变成所有路线的最优选择。
- **If 一名球员在一次训练后跨过关键成长阈值**: 系统必须触发明确的成长反馈或里程碑提示；不得把重要成长变化静默埋在后台数值里。
- **If 招募得到的新球员当前属性很低但训练效率很高**: 系统必须允许这类“低起点高成长性价比”对象存在，作为普通玩家可理解的长期投资选项。
- **If 招募得到的新球员初始属性很高但训练效率偏低**: 系统必须允许这类“即战力高但后续成长慢”的对象存在，支撑不同阶段的阵容选择。
- **If 训练结算完成但存档点尚未到达稳定节点**: 本次训练结果必须先作为已确认长期状态等待进入最近稳定落档点；不得在读档后重复结算或丢失。
- **If 比赛系统回传的赛后状态变化与培养系统当前球员状态冲突**: 冲突不得静默覆盖；必须按统一权威顺序处理，并标记该球员状态需要复核。
- **If 下游系统尝试直接改写球员长期属性或潜力上限**: 该改写必须视为无效，除非它通过培养系统或数值系统已声明的正式接口完成。
- **If MVP 阶段尚未实现复杂特性树、个性化事件链或深度位置专精**: 培养系统仍必须至少验证“不同球员练起来真的不一样，而且这些差异会影响比赛价值”的最小闭环。
- **If 玩家无法从 UI 看懂某名球员为什么值得继续投入**: 视为培养反馈失败；系统必须至少让玩家理解该球员的短板、潜力层级、训练效率倾向和当前培养定位。

## Dependencies

运动员培养系统位于 Core 层，是《足球小镇》从 Foundation 规则走向可玩主循环的第一层核心承接者。它本身不拥有共享属性边界、统一时间轴或持久化机制，但负责把这些基础规则转化为玩家可操作、可规划、可比较的球员成长过程。对上，它依赖数值系统、时间与赛季推进系统、存档与读档系统；对下，它为比赛、技能、事件、UI 和引导等多个系统提供球队成长的主要输入。

### Dependency Rules

1. 运动员培养系统负责“球员如何成长”，不负责“共享公式是否合法”“时间如何推进”或“存档如何落盘”；这些边界必须分别服从上游 Foundation 系统。
2. 任何下游系统若希望新增球员长期字段、改变潜力层级逻辑、或直接改写训练效率，必须先回到本系统修订，而不能在本地 GDD 中静默覆盖。
3. 比赛、技能、事件、UI 等系统可以消费球员成长结果，但不能各自定义一套独立的球员成长语义，否则会破坏培养系统的权威性。
4. 当后续 GDD 完成时，依赖关系必须双向成立：本节列出的下游系统，需要在它们各自的 Dependencies 或 Interactions 章节中反向声明“依赖运动员培养系统”。
5. 如果某个系统只展示培养结果而不改变球员长期成长状态，则它对本系统属于软依赖；如果某个系统会生成、消耗、改变或持久化球员成长状态，则属于硬依赖。
6. 在 MVP 阶段，比赛竞技系统、主循环 UI 框架、球员管理 UI 和新手引导系统是最关键的承接者；它们必须优先验证玩家能否看懂“为什么这个球员值得练、练完强在哪里”。
7. 本系统必须优先维护“普通球员短期更值、明星球员长期更强”的差异化培养逻辑；若下游系统让所有路线都同样最优，应优先回到本系统和数值系统复核，而不是在下游打补丁。

## Tuning Knobs

本节仅包含运动员培养系统拥有的共享调参项，不包含比赛胜率斜率、赛季长度、全局资源产出或技能效果表。它们控制的是“谁更值得练、多久能练出来、普通与明星差异是否成立”，而不是下游系统的业务内容本身。

| 调参项 | 控制内容 | 安全范围 | 调高风险 | 调低风险 | 主要影响 |
|---|---|---|---|---|---|
| 基础训练效率范围 `training_efficiency_band` | 全体球员训练效率分布的整体跨度 | `0.8` 至 `1.5` | 个体差异过大，少数球员会碾压所有培养路线 | 球员同质化明显，培养对象缺乏选择意义 | 球员差异化、培养辨识度 |
| 普通球员潜力上限区间 `normal_tier_potential_band` | 普通球员的默认潜力范围 | `60` 至 `75` | 普通球员后期过强，稀释明星球员价值 | 普通过渡球员太快淘汰，前期阵容缺乏培养意义 | 前期培养价值、过渡阵容体验 |
| 优秀球员潜力上限区间 `strong_tier_potential_band` | 优秀球员的默认潜力范围 | `70` 至 `85` | 中层球员过度万能，压缩其他层级特色 | 中层断层明显，培养路线太两极 | 中期阵容稳定性、培养平滑度 |
| 明星球员潜力上限区间 `star_tier_potential_band` | 明星球员的默认潜力范围 | `85` 至 `95` | 明星球员过早形成绝对最优答案 | 明星投入吸引力不足，长期目标感变弱 | 长期回报感、核心养成欲望 |
| 传奇胚子潜力上限区间 `legend_tier_potential_band` | 极高端培养对象的默认潜力范围 | `92` 至 `100` | 终局成长过强，其他路线失去意义 | 终局培养缺乏梦想感与追求空间 | 终局幻想、稀有目标价值 |
| 训练匹配倍率范围 `training_focus_match_multiplier_band` | 训练项目与球员定位匹配时的效率波动 | `0.7` 至 `1.3` | 正确路线收益过高，错误路线完全失效 | 培养方向差异不明显，训练选择失去规划意义 | 训练规划感、路线清晰度 |
| 状态修正下限 `condition_penalty_floor` | 高疲劳/低状态时训练效率允许降低到的最低值 | `0.5` 至 `0.8` | 状态惩罚太重，训练挫败感明显 | 状态系统存在感不足，恢复管理失去意义 | 低压力体验、状态管理感 |
| 单次训练基础成长输入 `raw_growth_input_standard` | 常规训练项目提供的基础成长输入 | `1.0` 至 `4.0` | 成长过快，短期内大量撞上限 | 成长过慢，训练反馈不足 | 单次训练爽感、成长节奏 |
| 短期 ROI 目标差 `short_term_roi_gap_target` | 普通球员相对明星球员在前期训练中的性价比领先幅度 | `10%` 至 `30%` | 普通球员长期都最值，明星线失效 | 前期全都该堆明星，普通球员沦为废档 | 前期策略取舍、不同层级定位 |
| 长期回报差 `long_term_ceiling_gap_target` | 明星/传奇球员相对普通球员的后期上限优势 | `10` 至 `25` 属性点级差 | 高潜力路线后期过度锁定最优 | 长期培养缺乏兑现感 | 长期梦想感、终局队伍构筑 |
| 多属性副成长占比 `secondary_attribute_gain_ratio` | 一次训练带动副属性成长的比例 | 主属性收益的 `10%` 至 `35%` | 一次训练收益过全能，路线选择失真 | 属性成长过于单线程，球员塑形太僵硬 | 球员塑形感、训练价值密度 |
| 里程碑反馈频率 `development_milestone_frequency_target` | 多久出现一次明显培养里程碑反馈 | 每 `3` 至 `8` 次有效训练一次 | 提示过密，成长被噪音稀释 | 提示过稀，玩家难感知长期投入痕迹 | 成就感、陪伴感 |
| 单名球员集中培养压力 `focus_training_pressure_target` | 连续集中培养同一球员时应感受到的机会成本强度 | `中` 至 `高` | 集中培养太亏，核心养成幻想被抑制 | 免费滚雪球，其他球员培养失去意义 | 阵容平衡、核心养成选择 |
| 招募后可读性阈值 `new_recruit_readability_target` | 新球员在加入时应被玩家迅速理解的成长信息量 | `3` 至 `5` 个关键字段 | 信息过多，招募判断负担过高 | 信息过少，玩家难判断值不值得练 | 招募判断效率、培养预期管理 |

## Acceptance Criteria

### 球员差异化

- **GIVEN** QA 从四类球员层级（普通/优秀/明星/传奇胚子）各抽样至少 3 名球员，**WHEN** 检查其培养面板，**THEN** 至少以下字段之一在不同层级间存在统计显著差异：`potential_cap`、`training_efficiency`、`player_tier`（分层归属标签）。同层级内允许个体差异但不得全部同值。
- **GIVEN** 两名球员接受相同训练项目且其他条件一致（相同状态、相同设施倍率），**WHEN** QA 比较训练结算结果，**THEN** `training_efficiency` 更高的球员必须获得更高的 `training_actual_gain`，除非已受到 `potential_cap - current_attribute = 0` 限制。
- **GIVEN** 一名球员处于高疲劳、低心情或恢复中状态，**WHEN** QA 执行一次训练，**THEN** `fatigue_adjusted_training_efficiency` 必须低于其基础 `training_efficiency`（除非基础值已触及 clamp 下限 0.5），且 UI 必须展示收益下降原因。

### 属性上限与成长

- **GIVEN** 一名球员某项属性已达到 `potential_cap`，**WHEN** QA 再次对该属性执行对应训练，**THEN** `training_actual_gain` 返回 0，且系统反馈”该属性已触及当前成长上限”。
- **GIVEN** `potential_cap < current_attribute ≤ 100`（逆输入边界），**WHEN** 执行成长结算，**THEN** `potential_cap` 被规范化为 `current_attribute`，保留已获得的永久成长值，该球员标记为需复核。

### 短期 vs 长期 ROI

- **GIVEN** 一名普通球员与一名明星球员在各自前 10 次训练内接受相同训练项目与消耗，**WHEN** QA 计算每次训练的 `player_development_roi`，**THEN** 普通球员在前 10 次的平均 ROI 必须 ≥ 明星球员平均 ROI 的 90%（即普通短期性价比不低于明星的九成），并在 `short_term_roi_gap_target`（10%–30%）的调参范围内可调出”普通更高”的结果。
- **GIVEN** 一名普通球员与一名明星球员均达到各自潜力上限，**WHEN** QA 比较其最终五维属性均值，**THEN** 明星球员的均值必须 ≥ 普通球员均值 + `long_term_ceiling_gap_target` 下限（10 属性点）。

### 招募信息

- **GIVEN** 一个新招募球员进入 roster，**WHEN** QA 查看其成长信息，**THEN** 至少展示：当前强弱项（≥2 项最高/最低属性标注）、潜力层级标签、训练效率倾向（高/中/低）、预期培养定位（短期轮换/中期主力/长期核心）。

### 训练匹配与副属性

- **GIVEN** 玩家选择一个与球员定位高度匹配的训练项目，**WHEN** QA 与不匹配训练项目对照测试，**THEN** 匹配项目的 `training_focus_match_multiplier` ≥ 1.0；不匹配项目 ≤ 1.0，且匹配项目的实际成长收益 > 不匹配项目。
- **GIVEN** 一次训练项目带来主属性和副属性成长，**WHEN** QA 核对结算结果，**THEN** 主属性收益 ≥ 副属性合计收益，且副属性合计占比在主属性收益的 `10%–35%` 范围内。

### 机会成本

- **GIVEN** 玩家连续 5 次训练集中培养同一名球员，**WHEN** QA 统计同期全队未训练球员的属性成长停滞天数，**THEN** 同期其他球员的属性成长均为 0（因未分配训练窗口），即集中培养的机会成本体现为其他球员成长停滞。
- **GIVEN** 玩家在前 30 次训练中主要培养普通球员（≥60% 训练次数分配给普通层级），**WHEN** QA 推进至 60 次训练后比较阵容平均属性，**THEN** 普通球员为主的阵容平均属性 ≤ 同期以明星球员为主的阵容平均属性 − 5 点（体现长期天花板约束）。

### 成长持久化

- **GIVEN** 玩家完成一次训练结算，**WHEN** QA 检查球员长期状态，**THEN** 本次训练结果立即写入该球员的权威成长状态，并等待最近稳定节点持久化；结果不得仅停留在临时显示层。
- **GIVEN** 玩家读档恢复到一个已完成训练的稳定节点，**WHEN** QA 检查对应球员的属性和培养状态，**THEN** 已确认的训练成长不得丢失，也不得重复结算。
- **GIVEN** `facility_training_multiplier = 1.0`（无任何设施），**WHEN** QA 执行训练结算，**THEN** `training_actual_gain` 结果与 Formula 2 在倍率=1.0 时的手工计算结果一致——无设施时训练不被错误压低或放大。

### 成长里程碑

- **GIVEN** 一名球员的任意属性首次达到以下阈值之一：`current_attribute` 跨过 10 的整数倍（10/20/…/90）、或累计训练次数达到 10/25/50 次，**WHEN** 该次训练结算完成，**THEN** 系统触发明确的成长里程碑提示（如”SPD 突破 70！”或”完成第 25 次训练”）。

### 比赛状态消费

- **GIVEN** 比赛系统回传赛后状态变化（如疲劳 +10%、心情 −5%），**WHEN** QA 让同一球员在赛后进入培养界面，**THEN** 培养系统消费这些状态变化：`condition_multiplier` 和 `morale_multiplier` 在下次训练结算时反映赛后的最新值。

### 训练资源扣除

- **GIVEN** 一次训练被确认执行，**WHEN** QA 检查资源变化，**THEN** 经费扣除量 = 该训练项目声明的 `funds_cost`；运动点数扣除量 = 该训练项目声明的 `ap_cost`；时间系统登记的行动窗口数 = 该训练项目声明的 `time_cost_slots`。三项扣除均在训练结算前完成。

### MVP 闭环

- **[Manual Playtest]** **GIVEN** MVP 版本完整实现，**WHEN** QA 从新档连续游玩 30 分钟，**THEN** 玩家能完整经历”查看球员差异 → 选择训练对象 → 消耗资源与时间 → 获得成长反馈 → 感知比赛价值变化”的闭环。此 AC 为手动 playtest，不要求自动化。

### 分层边界与 ROI 验证

- **GIVEN** QA 对四类球员层级各采样 ≥ 5 名球员，**WHEN** 检查其 `potential_cap`，**THEN** 每名球员的潜力上限落在本系统定义的对应该层级区间内（普通 60–75 / 优秀 70–85 / 明星 85–95 / 传奇 92–100），特殊个体需标记来源。
- **GIVEN** QA 采集四类球员各 10 次训练的 ROI 样本，**WHEN** 分别计算前 10 次平均 ROI 和后 10 次（第 20–30 次训练）平均 ROI，**THEN** 前 10 次：普通球员平均 ROI ≥ 明星球员平均 ROI × 0.9；后 10 次：明星球员平均 ROI > 普通球员平均 ROI（即 ROI 曲线在中期交叉）。不通过时标记为调优未完成，不得进入 Locked。
- **GIVEN** 玩家无法从培养界面判断某名球员值不值得继续投入，**WHEN** QA 检查培养信息展示，**THEN** 确认至少缺少以下字段之一：当前强弱项标注、训练效率倾向、潜力层级标签、近期成长速率摘要（最近 5 次训练的平均属性增量）。任一字段缺失即视为培养反馈失败。
- **GIVEN** 下游系统尝试直接改写球员长期属性、潜力上限或训练效率，**WHEN** QA 检查成长来源，**THEN** 这些变化只能通过本系统或数值系统声明的正式接口生效；绕过培养系统的改写操作被拒绝并记录错误。
