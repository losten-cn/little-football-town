## Overview

《足球小镇》是一款以“轻度足球经营 + 像素风格养成”为核心定位的单机模拟经营游戏。玩家将经营一座以足球为主题的小镇，通过招募、培养和管理球员，逐步建设训练设施、安排比赛赛程、优化资源分配，并带领球队从地方联赛一路成长到世界级舞台。游戏以“运动员培养 + 比赛竞技”为双核循环，以小镇建设、经济管理、成就声望和随机事件作为支撑系统，目标是在策略深度、可读性和轻松节奏之间取得平衡，提供一段既有成长满足感又没有强对抗压力的长期体验。

## Player Fantasy

玩家的核心幻想是“亲手经营一座梦想中的足球小镇，并培养出属于自己的传奇球队与足球巨星”。这份幻想包含三个层面：第一，作为经营者，玩家会体验从无到有建设足球小镇、规划设施和资源的掌控感；第二，作为教练与培养者，玩家会感受到看着普通球员逐渐成长为明星甚至传奇的情感投入；第三，作为球队领导者，玩家会在关键比赛、联赛晋级和世界舞台中获得荣誉感与成就感。整体情绪目标不是高压竞技，而是“温馨、投入、持续变强”的长期陪伴式成长体验。

### Target Audience

《足球小镇》的核心目标受众是喜欢轻度经营、角色成长和长期养成反馈的 PC 单机玩家。他们希望做出有意义的资源与培养决策，但不希望被高压竞技、复杂表格或强制在线节奏压迫。次级受众包括喜欢像素小镇、美术氛围、队伍养成和低失败惩罚模拟体验的玩家。

本游戏不以硬核足球战术玩家、实时动作竞技玩家或深度 spreadsheet 管理模拟玩家为第一目标。足球主题用于承载成长、陪伴、比赛反馈和小镇归属感，而不是复刻专业足球经理软件的全部复杂度。

### Game Pillars and Anti-Pillars

#### Pillar 1: 轻度足球经营

玩家应始终能理解当前球队状态、下一步目标和关键取舍。足球经营要提供策略感，但不能变成信息压迫或表格劳动。

**Design Test:** 如果一个功能需要玩家频繁对比大量细碎数据才能做出基本决策，它就违背了本支柱，除非该复杂度被清晰分层并保持可跳过。

#### Pillar 2: 像素小镇养成

小镇不是单纯的资源产出面板，而是玩家想要照顾、扩建和回到的地方。建设、界面和反馈都应强化“这是我的足球小镇”的归属感。

**Design Test:** 如果一个建设或表现决策只提升效率，却不能让小镇更有生活感、成长感或地方身份，它不应成为优先内容。

#### Pillar 3: 低压力长期成长

失败、资源紧张和比赛波动都应推动玩家调整路线，而不是制造惩罚感或不可逆挫败。游戏应让玩家相信继续经营总会带来可见进步。

**Design Test:** 如果一次失败会让玩家觉得被系统惩罚、失去恢复路径或必须重开，它就违背了本支柱。

#### Anti-Pillars

- 不做高压 PvP、排行榜焦虑或限时在线留存压力。
- 不做专业足球经理级别的深度战术表格模拟。
- 不做以惩罚、破产、永久失败为主要驱动力的硬核经营。
- 不用复杂 UI 密度替代有意义的经营选择。
- 不让足球比赛的刺激感压过日常小镇经营的温暖基调。

### Visual Identity Anchor

**One-line Visual Rule:** “一个你想住进去的像素小镇，和一支你想亲手执教的足球队。”

当视觉决策存在歧义时，优先选择温暖、清晰、可亲近的方案，而不是强烈、密集或压迫性的方案。

#### Supporting Visual Principles

1. **清晰先于密度**
   所有界面和场景都应先保证玩家一眼看懂当前重点。信息密度需要分层呈现，不能用堆叠面板、细碎数字或高对比装饰制造管理压力。
2. **成长像生活，不像网格优化**
   小镇建设应看起来是被逐步照顾和经营出来的生活空间，而不是冷冰冰的最优布局棋盘。建筑、道路、居民和足球元素都应服务“想回到这里”的感觉。
3. **挫折也要向前**
   输球、资源不足或进度放缓时，视觉反馈应传达“调整路线后还能继续成长”，而不是失败、惩罚或危机。比赛日可以有高能量峰值，但日常经营必须保持温暖和低压力。

## Detailed Rules

### Core Rules

1. 玩家扮演小镇经营者兼球队管理者，通过日常经营、球员培养和比赛推进游戏进程。
2. 游戏的核心正反馈来自“双核循环”：
   - 培养球员提升阵容实力；
   - 参加比赛获得奖励、经验与成长机会；
   - 比赛成果反过来推动更多建设与培养投入。
3. 玩家需要在三类主要资源之间做出分配决策：
   - 经费：用于招募、建设、维护与运营；
   - 研究点数：用于解锁功能、升级系统与深化策略空间；
   - 运动点数：用于训练、比赛和高价值行动。
4. 玩家推进节奏主要由资源、解锁条件和阶段目标控制，而不是由长时间等待控制。
5. 游戏包含三层循环：
   - 短期循环：日常训练、安排比赛、收取收益、做出局部经营决策；
   - 中期循环：完成赛季、提升声望、解锁新系统与新内容；
   - 长期循环：培养传奇球员、征战高级赛事、完成通关与多周目挑战。
6. MVP 阶段优先验证核心循环趣味性，仅保留最关键的培养、比赛和基础 UI 功能；邻接效应、随机事件、成就、多周目等扩展内容可以延后。
7. 游戏定位为单机、低压力体验，不依赖 PvP 压力或体力售卖机制驱动玩家留存。
8. 玩家每次登录都应当有明确的下一步目标，例如完成训练、准备比赛、提升关键球员、解锁设施或推进赛季进度。

### States and Transitions

| 状态 | 描述 | 进入条件 | 退出条件 | 转移目标 |
|---|---|---|---|---|
| 新手起步 | 玩家刚开始经营小镇，资源和功能有限 | 新建存档 | 完成基础引导并解锁核心界面 | 日常经营 |
| 日常经营 | 玩家进行训练、建设、资源管理和阵容调整 | 完成引导或赛后返回主循环 | 开始比赛、触发阶段性结算、解锁新内容 | 比赛准备 / 阶段结算 / 内容解锁 |
| 比赛准备 | 玩家配置阵容、战术或参赛信息 | 玩家选择进入比赛 | 确认开赛或取消 | 比赛进行 / 日常经营 |
| 比赛进行 | 系统执行比赛演算并反馈结果 | 比赛开始 | 比赛结束 | 赛后结算 |
| 赛后结算 | 展示奖励、成长结果、伤病/状态变化等 | 比赛结束 | 玩家确认结算结果 | 日常经营 / 阶段结算 |
| 阶段结算 | 一个赛季、一个阶段目标或一次重要解锁完成后的总结节点 | 达成赛季结束或阶段目标 | 玩家进入下一阶段 | 日常经营 / 内容解锁 |
| 内容解锁 | 玩家解锁新的系统、设施、联赛或挑战内容 | 声望、赛季、条件满足 | 玩家确认并开始使用新内容 | 日常经营 |
| 长期完成态 | 玩家达到高阶终局目标，如冠军、世界杯、通关 | 达成长期目标 | 开启多周目或继续自由游玩 | 新周目 / 自由持续经营 |

### Interactions with Other Systems

1. 与球员培养系统的交互：
   - 本文档定义培养是核心驱动之一；
   - 培养系统负责球员成长、训练收益、状态变化和长期发展。
2. 与比赛系统的交互：
   - 本文档定义比赛是另一核心驱动；
   - 比赛系统负责阵容投入后的结果反馈、奖励发放与竞争目标推进。
3. 与小镇建设系统的交互：
   - 概念层面上，小镇建设负责提供成长环境、功能解锁与长期规划空间；
   - 建设结果应反向增强培养和比赛表现。
4. 与经济系统的交互：
   - 经济系统负责限制扩张速度并形成资源分配压力；
   - 玩家对建设、招募、比赛和升级的取舍都应受到经济约束。
5. 与声望/成就系统的交互：
   - 声望系统承担“阶段性成长”职责；
   - 成就系统承担“长期收集与回访动机”职责。
6. 与随机事件系统的交互：
   - 随机事件用于丰富世界活力、制造变化和提供临时决策点；
   - 在 MVP 阶段可暂不纳入核心必需范围。
7. 与 UI/UX 系统的交互：
   - UI 必须支持玩家快速理解资源状态、当前目标、球员状态和比赛入口；
   - 所有主循环信息都需要被高可读性地呈现。
8. 与音频系统的交互：
   - 音频负责强化温馨、活力、成长与比赛情绪；
   - 在早期阶段可先用占位内容支撑核心验证。

## Formulas

本概念文档只定义概念级公式与目标关系，不锁定具体数值。详细数值应由后续平衡类 GDD 进一步明确。

### 1. 核心循环收益关系

The `core_progress` formula is defined as:

`core_progress = player_growth + match_reward + system_unlock_progress`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 玩家成长值 | `player_growth` | float | ≥ 0 | 由训练、升级、技能获得的综合成长收益 |
| 比赛奖励值 | `match_reward` | float | ≥ 0 | 由比赛胜负、表现和阶段奖励带来的综合收益 |
| 系统解锁推进值 | `system_unlock_progress` | float | ≥ 0 | 由声望、建设、赛季进度带来的解锁推进收益 |

**Output Range:** 正常游玩下为持续正增长；早期增长较小，中后期增长幅度随系统开放而提升。
**Example:** 若某次循环中玩家成长值为 12，比赛奖励值为 8，系统解锁推进值为 5，则 `core_progress = 25`。

### 2. 资源决策压力关系

The `decision_pressure` formula is defined as:

`decision_pressure = desired_actions - available_resources_support`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 期望行动量 | `desired_actions` | float | ≥ 0 | 玩家当前想执行的培养、建设、比赛等行动总需求 |
| 资源支持量 | `available_resources_support` | float | ≥ 0 | 当前经费、研究点数、运动点数可支撑的行动能力 |

**Output Range:** 当输出接近 0 时，说明当前资源供需平衡；当输出持续增大时，说明玩家必须做出更多取舍。
**Example:** 若玩家本轮想做 10 个单位的行动，但资源只能支撑 6 个单位，则 `decision_pressure = 4`。

### 3. 长期留存动机关系

The `retention_drive` formula is defined as:

`retention_drive = short_term_goal_clarity + mid_term_progress + long_term_aspiration`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 短期目标清晰度 | `short_term_goal_clarity` | float | 0–1 | 玩家是否清楚知道“现在该做什么” |
| 中期进度反馈 | `mid_term_progress` | float | 0–1 | 玩家是否稳定感受到赛季、解锁和成长推进 |
| 长期愿景吸引力 | `long_term_aspiration` | float | 0–1 | 玩家是否相信继续投入会带来更大成就 |

**Output Range:** 0–3；越高表示越容易形成稳定持续游玩动力。
**Example:** 若短期目标清晰度 0.9、中期进度反馈 0.7、长期愿景吸引力 0.8，则 `retention_drive = 2.4`。

## Edge Cases

- **如果玩家资源不足以同时进行训练、建设和比赛**：系统必须迫使玩家做出优先级选择，而不是允许无成本全做。
- **如果玩家连续输掉比赛**：游戏应仍提供可恢复的成长路径，避免一次失败导致长期停滞。
- **如果玩家只专注培养、不重视比赛**：系统应允许这种玩法短期成立，但长期推进应因比赛奖励不足而受限。
- **如果玩家只专注比赛、不投入建设或培养**：系统应允许快速推进部分赛程，但中后期会因成长与资源基础薄弱而受阻。
- **如果核心循环在 MVP 测试中无法支撑 30 分钟以上的会话兴趣**：该结果视为概念风险验证失败，必须优先调整核心循环，而不是盲目增加外围内容。
- **如果多平台适配带来交互复杂度显著提升**：PC 版本应被视为优先基线，其他平台在不破坏核心体验的前提下做约束性适配。
- **如果存档损坏或升级后不兼容**：概念上要求后续架构和实现提供版本迁移、验证与恢复策略。
- **如果随机事件、成就或多周目等扩展系统尚未完成**：基础版本仍必须能独立证明培养与比赛循环本身有趣。

## Dependencies

本概念文档依赖以下后续系统文档被进一步细化：

1. 球员培养系统 GDD
   - 定义属性、成长、训练、技能、状态与球员生命周期。
2. 比赛竞技系统 GDD
   - 定义比赛流程、阵型、战术、结果演算与赛后反馈。
3. 小镇建设系统 GDD
   - 定义设施建造、升级、布局与长期扩张结构。
4. 经济系统 GDD
   - 定义资源获取、消耗、节奏控制与经营压力来源。
5. 声望与成就系统 GDD
   - 定义阶段解锁、长期目标与收集动力。
6. 随机事件系统 GDD
   - 定义非线性变化、叙事插曲与临时决策。
7. UI/UX 规范
   - 定义信息架构、主循环入口、可读性和多平台适配方式。
8. 音频设计文档
   - 定义情绪层级、比赛反馈、环境氛围与成长情感表达。
9. 后续 ADR
   - 负责定义技术选型、存档结构、数据驱动方案和跨平台实现策略。

## Tuning Knobs

以下为概念阶段已确认、后续必须数据化的调节旋钮：

| 调节项 | 说明 | 调高效果 | 调低效果 |
|---|---|---|---|
| 球员成长速度 | 控制培养反馈强弱 | 更爽快、更快达成成长 | 更克制、更耐玩但可能拖沓 |
| 比赛奖励强度 | 控制比赛对主循环的推动力 | 鼓励频繁比赛 | 比赛重要性下降 |
| 资源产出速度 | 控制扩张与决策压力 | 经营压力降低 | 取舍更明显 |
| 资源消耗强度 | 控制玩家做选择的必要性 | 节奏更紧、挑战更强 | 更宽松、更休闲 |
| 声望解锁速度 | 控制中期目标推进效率 | 更快看到新内容 | 更强调长期规划 |
| 小镇建设收益倍率 | 控制建设系统的重要性 | 更鼓励建设投入 | 更偏向纯培养/比赛路线 |
| 失败恢复弹性 | 控制输球后的挫败感 | 更友好、更休闲 | 更强调挑战性 |
| 多周目继承力度 | 控制重玩价值结构 | 更易开启长线循环 | 更强调首周目完整体验 |

## Acceptance Criteria

- **GIVEN** 玩家开始新游戏，**WHEN** 完成基础引导，**THEN** 玩家应能进入一个包含培养、比赛和基础经营决策的可玩主循环。
- **GIVEN** 玩家完成若干次训练与至少一场比赛，**WHEN** 返回主循环，**THEN** 玩家应能明显感知球员成长、资源变化或进度推进。
- **GIVEN** 玩家在资源有限的情况下同时面临多项可执行行动，**WHEN** 尝试推进主循环，**THEN** 系统应迫使玩家进行取舍，而不是无条件全量执行。
- **GIVEN** 玩家持续推进一个赛季，**WHEN** 达成阶段性目标，**THEN** 游戏应提供新的解锁、成长反馈或中期目标，形成继续游玩的动力。
- **GIVEN** MVP 版本完成，**WHEN** 进行内部测试，**THEN** 核心循环应能够支撑约 30 分钟以上的单次会话，并让测试者理解“继续玩下去”的理由。
- **GIVEN** 玩家连续遭遇失败或资源紧张，**WHEN** 尝试恢复进度，**THEN** 游戏应提供可逆转的成长路径，而不是进入不可恢复的停滞状态。
- **GIVEN** 游戏进入长期阶段，**WHEN** 玩家接近高阶赛事、传奇球员培养或多周目解锁，**THEN** 游戏应继续提供足够清晰的长期目标与回报预期。
- **GIVEN** 项目进入后续设计拆分阶段，**WHEN** 各系统 GDD 被进一步编写，**THEN** 它们必须能从本概念文档追溯到“双核循环 + 四大支撑系统 + 三层目标”的总体验目标。
