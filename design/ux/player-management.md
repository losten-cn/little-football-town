## Purpose & Player Need

球员管理界面是玩家"了解自己球队"的地方。它回答四个问题：**我有哪些球员？每个人强在哪弱在哪？谁值得我投入培养资源？培养之后变化了多少？**

它本身不做任何游戏逻辑——不计算训练收益、不判定成长幅度、不修改属性值——而是把运动员培养系统（ADR-0005）的数据转化为可浏览、可比较、可决策的视觉呈现。

MVP 核心目标：玩家能在 30 秒内从球员列表中找到值得关注的球员，看懂他的强弱项和培养价值，并知道下一步该去哪里培养他。

这个界面包含两个子视图：
- **球员列表 (Roster)** — 排序、筛选、快速判断谁值得关注
- **球员详情 (Player Detail)** — 五维属性雷达、成长轨迹、培养入口

## Player Context on Arrival

| 到达场景 | 情绪状态 | 设计含义 |
|----------|----------|----------|
| 从主视图浏览球队 | 平静、审慎——评估阵容 | 列表默认综合评分降序，优先展示最强球员 |
| 比赛后查看变化 | 好奇、关注——谁涨了谁伤了 | 近期成长指示需醒目，状态变化清晰可见 |
| 准备训练前 | 决策中——比较谁最值得投入 | 列表信息密度应支持横向比较，无需点进详情 |
| 新档首次打开 | 探索——没有或很少球员 | 空列表引导提示 + 招募入口可见 |

## Navigation Position

```
主菜单 (L0) → 小镇主视图 (L1) → 球员列表 Roster (L2) → 球员详情 Player Detail (L3)
```

球员管理 UI 嵌入主循环 UI 框架的两个容器：Roster 和 Player Detail。导航深度 L2 = 深度 1，L3 = 深度 2，符合框架的 ≤3 约束。

## Layout Specification

### Information Hierarchy

**Roster（球员列表）**

| 层级 | 信息 | 说明 |
|------|------|------|
| **L1** 一眼可见 | 球员摘要（头像+名字+综合评分+位置+状态标签） | 卡片首行，最优先信息 |
| **L2** 主动浏览 | 五维属性简值 + 潜力 + 培养层级 + 稀有度星级 | 卡片展开区，横向比较 |
| **L3** 按需操作 | 排序/筛选控件 + 招募入口 | 底部固定区域 |

**Player Detail（球员详情）**

| 层级 | 信息 | 说明 |
|------|------|------|
| **L1** 一眼可见 | 名字 + 立绘 + 综合评分 + 培养层级 + 当前状态 | 左栏顶部，身份锚点 |
| **L2** 主动浏览 | 五维属性雷达（当前值+潜力上限双线） | 核心差异化信息 |
| **L3** 按需探索 | 成长轨迹 + 历史记录 | 可展开/可滚动 |
| **L3** 非 MVP 占位 | 技能信息区（如未来系统接入） | MVP 默认隐藏，不占固定信息层级 |
| **L3** 按需操作 | 培养按钮 + 训练安排按钮 | 底部固定操作区 |

### Layout Zones

**Roster 布局：**
```
┌─ 标题栏 (← 返回 + 球员管理 + 🔍搜索 + ⚙筛选) ────────────┐
├─ 标签筛选栏 ([全部] [主力] [替补] [青训] [伤病]) ──────────┤
├─ 滚动列表区 (球员行 × N) ─────────────────────────────────┤
├─ 底部栏 ([招募新球员] + 排序控件) ────────────────────────┤
└────────────────────────────────────────────────────────────┘
```

**Player Detail 布局：**
```
┌─ 标题栏 (← 返回 + 球员名 + [解雇]) ────────────────┐
├─ 左栏 (立绘+换装) ─┬─ 右栏 (基础信息+状态+合同) ──────────┤
├─ 五维雷达图区 ────────────────────────────────────────────┤
├─ 成长轨迹 / 历史记录区 ───────────────────────────────────┤
├─ 底部操作栏 ([培养] [安排训练] [查看历史]) ───────────────┤
└────────────────────────────────────────────────────────────┘
```

非 MVP future placeholder：若未来技能系统接入，可在成长轨迹区下方追加「技能信息区」，但 MVP 默认隐藏，不预留常驻可见槽位。

## States & Variants

| 状态 | 触发 | 变化 |
|------|------|------|
| **Default** | 正常加载，数据完整 | 如 Wireframe 所示 |
| **Empty** | 球队无球员 | 列表区显示引导文案「还没有球员——前往招募你的第一名球员」+ 招募按钮高亮 |
| **Loading** | 数据加载中 | 列表区骨架屏（灰色占位卡片 × 5） |
| **Filtered Empty** | 筛选条件无匹配 | 列表区显示「无匹配球员」+ 清除筛选链接 |
| **Injury Detail** | 球员伤病中 | 详情页状态区红色伤病标记 + 恢复倒计时 + 训练按钮禁用 |
| **At Cap** | 某属性已达潜力上限 | 雷达图该轴标记锁图标 + 显示「已达上限」 |
| **Error** | 数据加载失败（PlayerRoster 数据不可用、属性数据异常） | 对应区域显示错误占位「数据加载失败 — {原因}」+ [重试] 按钮；导航按钮（返回/标签切换）保持可用；其余正常区域不阻塞 |

## Interaction Map

输入环境：**Keyboard/Mouse only**。

### Roster View

| 操作 | 鼠标 | 键盘 | 结果 |
|------|------|------|------|
| 点击球员行 | 左键 | ↑↓ 选择 + Enter | → Player Detail |
| 切换分类标签 | 左键 | 1-5 | 即时过滤列表 |
| 搜索球员 | 点击输入框输入 | Tab→输入 | 即时过滤 |
| 排序切换 | 左键下拉 | Tab→Enter | 即时重排 |
| 返回 | ← 按钮 | ESC | → 小镇主视图 |
| 招募新球员 | 左键按钮 | Tab→Enter | → 招募界面 |

### Player Detail View

| 操作 | 鼠标 | 键盘 | 结果 |
|------|------|------|------|
| 雷达图悬停 | 悬停各轴 | Tab 逐轴 → Enter | Tooltip 显示精确值 + 距上限差距 |
| 培养 | 左键按钮 | Tab→Enter | → 训练界面（携带 `player_id`） |
| 安排训练 | 左键按钮 | Tab→Enter | → 训练安排（预选球员） |
| 查看历史 | 左键按钮 | Tab→Enter | 展开/折叠成长轨迹面板 |
| 返回 | ← 按钮 | ESC | → Roster（保持筛选和滚动位置） |

MVP 不提供「学习新技能」交互。若未来技能系统立项，该入口需在独立规格确认后再加入此表。

## Accessibility

无障碍层级：**WCAG-AA**（已正式承诺，详见 `design/accessibility-requirements.md`）。此界面满足以下要求，逐项对应 §8 Per-Screen Checklist：

| # | 检查项 | 状态 |
|---|--------|------|
| 1 | 可交互元素有可见焦点环（`#FFD700` 2px） | ✓ — 见下方焦点顺序 |
| 2 | Tab 焦点顺序与视觉布局一致 | ✓ — Roster: 返回→搜索→筛选→标签→列表行→排序→招募；Detail: 返回→雷达图→培养→训练→历史。非 MVP 技能信息区默认隐藏，不进入 Tab 顺序 |
| 3 | ESC 正确返回/关闭覆盖层 | ✓ — Roster 内 ESC 返回小镇主视图；Detail 内 ESC 返回 Roster（保持筛选和滚动位置） |
| 4 | 列表 ↑↓ 选择 + Enter 确认 | ✓ — Roster 列表行 ↑↓ 选择，Enter 进入详情 |
| 5 | 覆盖层焦点陷入，关闭后焦点回归 | N/A — 此界面无覆盖层 |
| 6 | 状态信息双通道（颜色+图标/文字） | ✓ — 引用 #21 Color-Blind Friendly；稀有度=边框+星级+文字；伤病=红色+🔴+「伤病中」 |
| 7 | 红/绿状态有图标备份 | ✓ — 伤病标记三重编码；状态标签颜色+图标+文字 |
| 8 | 正文对比度 ≥ 4.5:1，字号 ≥ 12px | ✓ — 引用 #20 Font Readability |
| 9 | 拖拽操作有非拖拽替代 | N/A — 此界面无拖拽操作 |
| 10 | 动画有 reduced-motion 替代 | ✓ — 所有过渡动画 50ms 淡入淡出 |
| 11 | 无快速频闪 (≥3次/秒) | ✓ — 无循环闪烁动画 |
| 12 | 加载 >500ms 有进度指示 | ✓ — Loading 状态有骨架屏（灰色占位卡片 ×5） |
| 13 | 空状态有引导文案+操作入口 | ✓ — Empty 状态显示「还没有球员——前往招募你的第一名球员」+ 招募按钮高亮 |
| 14 | 错误状态有原因+恢复路径 | ✓ — Error 状态显示「数据加载失败 — {原因}」+ [重试] 按钮 |
| 15 | 点击目标达到最小尺寸 | ✓ — 列表行高 64px；按钮使用 #3/#4 模式（最小 36×24px） |
| 16 | 关键 UI 元素有语义标记 | QQ-A11Y-01 — 待 Godot 4.6 AccessKit 验证。列表行播报「第 {N} 项：{球员名} — {位置} — 综合评分 {分数} — {状态}」；雷达图逐轴播报「{属性名} {当前值}/{潜力上限} — 潜力剩余 {差距}」；稀有度标签播报「{稀有度等级}」；伤病标记播报「伤病中 — 恢复剩余 {N} 周」 |
| 17 | 实时状态变更触发阅读器通知 | QQ-A11Y-01 — 同上。进入详情页播报球员名和综合评分；筛选后播报「{筛选条件} — {N} 名球员」 |
| 18 | 无时间限制操作 | ✓ — 无计时操作 |

**Reduced-motion**: 所有过渡动画缩短为 50ms 淡入淡出。

## Acceptance Criteria

- [ ] 球员列表从主视图点击「球员」后 300ms 内渲染，默认按综合评分降序排列
- [ ] 点击分类标签（全部/主力/替补/青训/伤病）即时过滤，不触发加载动画
- [ ] 搜索框输入姓名即时过滤，结果为空时显示「无匹配球员」提示
- [ ] 点击球员行进入 Player Detail，五维属性以雷达图展示当前值（实线）和潜力上限（虚线）
- [ ] 详情页「培养」按钮携带 player_id 跳转训练界面，球员已预选
- [ ] 已达潜力上限的属性在雷达图上有锁图标标记，培养界面该属性 [+] 按钮禁用
- [ ] Tab 键可在列表行之间导航，Enter 进入详情，ESC 返回上级
- [ ] 空球队时列表显示引导文案 + 招募按钮高亮，不显示空白崩溃
