# UX Spec: 小镇主视图（核心游玩界面）

> **Status**: In Design
> **Author**: nico + ux-designer
> **Last Updated**: 2026-05-18
> **Journey Phase(s)**: 日常经营
> **Template**: UX Spec
> **Platform Target**: PC（Windows primary；Linux secondary；Keyboard/Mouse only）

---

## Purpose & Player Need

小镇主视图是《足球小镇》在 MVP 阶段的核心 L1 Home 界面。它的职责被严格限定为两件事：

1. 让玩家在 3 秒内确认当前主循环状态：时间、经费、运动点数、可用行动窗口、下一场比赛状态。
2. 让玩家在 5 秒内进入当前真正需要的核心去向：球员管理或比赛流程。

它不是“所有系统的总控制台”，也不是未来功能入口的展示层。MVP 中，小镇主视图保留小镇/主场的归属感与中央地图主体，但所有常驻壳层必须与 `design/ux/hud.md` 的严格 MVP HUD 完全一致：

- 顶部状态栏
- 底部导航（仅球员、比赛）
- 中央地图主体作为 Home 内容区

因此，本界面不再承诺旧版侧边栏、五标签底栏、ticker/info bar、通知中心、统计面板、常驻声望、建设/商店/任务入口等壳层元素。

## Player Context on Arrival

玩家会在以下情境回到小镇主视图：

- **从主菜单进入**：开始或继续经营循环
- **从球员相关操作返回**：想确认资源、时间与下一步安排
- **从比赛结算返回**：想确认结果影响与后续节奏
- **从暂停菜单关闭后回到当前界面**：继续当前计划
- **从存档加载后进入**：快速恢复心智模型

到达前的情绪状态与设计含义：

| 到达场景 | 情绪状态 | 设计含义 |
|----------|----------|----------|
| 常规回归 | 平静、有目的 | HUD 信息必须稳定，不重新教学 |
| 新档首次到达 | 好奇、轻微不确定 | 用最少入口明确“先做什么” |
| 比赛日前回归 | 期待或紧张 | 比赛状态必须比背景信息更清楚 |
| 赛后回归 | 想确认变化 | 资源和时间更新必须第一时间可读 |
| 读档后回归 | 恢复计划 | 顶部栏应帮助玩家快速接上节奏 |

小镇主视图必须像“回到基地”一样可靠：结构固定、信息可信、去向明确。

## Navigation Position

小镇主视图是 MVP 阶段的唯一 L1 Home Hub：

**主菜单 (L0) → 小镇主视图 (L1) → 核心子界面 (L2)**

本界面在 MVP 中只直接承诺以下去向：

- **球员管理（Roster）**
- **比赛中心（Match Center）**
- **暂停菜单（Overlay，不离开 L1）**
- **日程界面（Schedule，仅当顶部日期元素已接入时）**

以下系统不属于本屏幕的 MVP 常驻导航承诺：建设、商店、统计、通知、任务、声望、研究点数。

## Entry & Exit Points

| 入口来源 | 触发方式 | 携带上下文 |
|----------|----------|------------|
| 主菜单 | 点击“继续游戏”或“新的旅程” | 存档状态或新档初始状态 |
| 球员管理 | 返回按钮 / `Esc` | 最新球员状态与资源结果 |
| 比赛结算 | 点击“返回”确认结果 | 最新比赛结果、时间推进、资源更新 |
| 存档加载 | 加载完成后自动进入 | 完整存档状态 |
| 暂停菜单 | 关闭覆盖层 | 返回进入前的小镇主视图状态 |

| 出口目标 | 触发方式 | MVP 规则 |
|----------|----------|-----------|
| 球员管理（Roster） | 底部“球员”按钮 / `R` / Tab→Enter | 始终可进入 |
| 比赛中心（Match Center） | 底部“比赛”按钮 / 顶部“下一场比赛”状态（仅在可进入时） / `M` / Tab→Enter | 仅满足比赛进入条件时可进入 |
| 暂停菜单 | 顶部菜单按钮 / `Esc` | 覆盖层，不离开主视图 |
| 日程界面（Schedule） | 顶部日期元素 | 仅在日程功能已接入时可用；否则日期只读 |

### 明确不作为 MVP 出口承诺的项目

以下目标在本屏幕中必须视为 **Non-MVP future placeholder** 或默认隐藏，不得作为常驻入口出现：

- 建设模式
- 商店
- 统计总览
- 通知中心
- 任务面板
- 声望/成就页
- 研究系统入口

## UI Structure & Layout Specification

### 1. HUD 壳层对齐规则

小镇主视图必须服从 `design/ux/hud.md` 的严格 MVP HUD，不得自定义第二套常驻外壳。固定结构只有三层：

- **Zone A: Top Status Bar**
- **Zone B: Central Town Map Body**
- **Zone C: Bottom Navigation**

其中：
- Zone A 负责状态扫描与全局入口
- Zone B 负责小镇/home 感与中央地图主体
- Zone C 只负责两个核心导航入口

### 2. Information Hierarchy

| 层级 | 信息项 | 位置 | 说明 |
|------|--------|------|------|
| **L1** 一眼可见 | 日期/赛季阶段 | 顶部状态栏 | 时间锚点 |
| **L1** 一眼可见 | 经费 | 顶部状态栏 | 核心经营资源 |
| **L1** 一眼可见 | 运动点数 | 顶部状态栏 | 行动资源 |
| **L1** 一眼可见 | 可用行动窗口 | 顶部状态栏 | 还能做几次行动 |
| **L1** 一眼可见 | 下一场比赛状态 | 顶部状态栏 | 比赛是否已可进入 |
| **L1** 一眼可见 | 菜单 | 顶部状态栏 | 暂停/系统入口 |
| **L1** 一眼可见 | 球员入口、比赛入口 | 底部导航 | 仅保留的两个核心去向 |
| **L2** 被动浏览 | 小镇中央地图主体 | 中央主内容区 | 提供归属感、环境反馈与轻量提示 |
| **Hidden / Non-MVP** | 建设、商店、通知、统计、任务、声望、研究点数 | 不在常驻 HUD 出现 | 未来功能默认隐藏 |

### 3. Layout Zones

```text

│ 日期/赛季 │ 经费 │ 运动点数 │ 行动窗口 │ 下一场比赛 │ 菜单 │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│                    Zone B: Central Town Map Body                          │
│             中央小镇地图主体、建筑轮廓、环境角色动画、轻量状态提示          │
│                                                                           │
├─ Zone C: Bottom Navigation (56px fixed) ──────────────────────────────────┤
│ 球员入口 │ 比赛入口 │
└───────────────────────────────────────────────────────────────────────────┘
```

### 4. Global Layout Rules

- 只允许 **顶部状态栏 + 中央地图主体 + 底部导航** 三段结构。
- 不允许左侧快捷栏。
- 不允许底部五标签条。
- 不允许 ticker/info bar。
- 不允许常驻通知入口、常驻统计入口、常驻声望入口。
- 建设、商店、任务、研究点数若在工程中已存在，也不得占据固定 HUD 槽位。
- 中央地图主体必须始终可见，不能被旧版面板式壳层挤压成次要背景。

### 5. Component Inventory

#### Zone A — 顶部状态栏

| 组件 | 类型 | 内容 | 交互 | MVP 规则 |
|------|------|------|------|----------|
| 日期/赛季 | Status Text / Context Button | 当前季节 + 周数 | 已接入 Schedule 时可点击；未接入时只读 | 不展开二级面板 |
| 经费 | Status Text | 当前经费 | 默认只读；可有简短 tooltip | 不承诺收支详情面板 |
| 运动点数 | Status Text + Short Fill | 当前/最大值 | 默认只读；可有简短 tooltip | 不承诺详细消耗展开 |
| 可用行动窗口 | Status Text | 当前可用次数 | 只读 | 不承诺点击明细 |
| 下一场比赛 | Status Capsule / Context Button | 对手名或状态文本 | 仅在比赛可进入时可点击 | reduced-motion 下静态高亮 |
| 菜单按钮 | Icon Button | 打开暂停菜单 | 点击 / `Esc` / Tab→Enter / Space | 关闭后焦点回到此按钮 |

#### Zone B — 中央小镇地图主体

| 组件 | 类型 | 内容 | 交互 | MVP 规则 |
|------|------|------|------|----------|

| 环境角色层 | Ambient Sprite Layer | 球员/NPC 的轻量循环动画 | 无 | 仅增强生气感 |
| 轻量状态提示 | Inline Helper Text/Card | 新档、比赛已可开始、行动耗尽等短文案 | 无主导航职能 | 只重复关键上下文，不替代 HUD |

#### Zone C — 底部导航

| 组件 | 类型 | 内容 | 交互 | MVP 规则 |
|------|------|------|------|----------|
| 球员入口 | Primary Nav Button | 进入球员管理 | 点击 / `R` / Tab→Enter | 球员数为 0 时仍可进入空状态界面 |
| 比赛入口 | Primary Nav Button | 进入比赛中心 | 点击 / `M` / Tab→Enter | 未满足条件时禁用并显示原因 |

## Non-MVP Boundary

为避免旧原型继续暗示“什么都能从主界面直接做”，本规格明确以下边界：

| 系统/入口 | MVP 状态 | 在小镇主视图中的处理 |
|-----------|----------|----------------------|
| 建设 | Non-MVP / Future | 不提供常驻入口，不提供模式开关，不提供网格覆盖 |
| 商店 | Non-MVP / Future | 不提供常驻入口 |
| 统计总览 | Non-MVP / Future | 不提供入口或常驻面板 |
| 通知中心 | Non-MVP / Future | 不提供铃铛入口；仅允许 Toast 作为轻量反馈 |
| 任务 | Non-MVP / Future | 不提供常驻标签或未读角标 |
| 声望/成就 | Non-MVP / Future | 不提供顶部常驻显示或直达入口 |
| 研究点数 | Hidden in MVP | 后台可存在，但不在本屏显示 |
| 可点击建筑/角色 | Future | 不是当前中央地图主体的默认能力 |

## States & Variants

| 状态/变体 | 触发条件 | 界面变化 |
|-----------|----------|----------|
| **Default** | 正常加载、数据完整 | 顶部状态栏与底部导航正常显示；中央地图主体处于默认浏览态 |
| **New Save / No Players** | 首次进入或球员数 = 0 | 球员入口保持可用；比赛入口禁用并说明原因；中央地图主体显示简短引导“先进入球员界面开始本周安排” |
| **Match Ready** | `match_trigger_reached = true` 且比赛中心可进入 | 顶部“下一场比赛”进入强调态；底部“比赛”入口同步可用并高亮 |
| **No Actions Left** | 可用行动窗口 = 0 且比赛未就绪 | 顶部行动窗口显示 `0 可用`；中央地图主体可显示低优先级提示，但不新增额外系统入口 |
| **Match Ready + No Actions Left** | `match_trigger_reached = true` 且可用行动窗口 = 0 | 比赛提醒优先；玩家的唯一明确主行动方向是进入比赛 |
| **Resource Warning** | 经费或运动点数低于阈值 | 对应状态项使用颜色 + 图标/文字双通道警示，不使用持续闪烁 |
| **Loading** | 存档加载或单项数据未就绪 | 各 HUD 元素独立进入局部加载态；中央地图主体显示静态占位或基础画面 |
| **Local Error** | 单一数据源失败 | 仅对应元素显示“未连接/不可用”；其余 HUD 与中央地图主体继续显示 |
| **Pause Overlay** | 打开暂停菜单 | HUD 与中央地图主体变暗、不可交互；焦点陷入暂停菜单 |
| **Match Fullscreen** | 进入 Match Pre / Match Live / Match Result | 比赛表现 UI 全屏接管；小镇主视图与 HUD 隐藏 |

已移除的旧状态：Build Mode、通知中心展开态、统计面板展开态、五标签切换态、ticker 播报态。

## Interaction Map

输入环境：**Keyboard/Mouse only**。

### Zone A — 顶部状态栏

| 组件 | 操作 | 鼠标 | 键盘 | 即时反馈 | 结果 |
|------|------|------|------|----------|------|
| 日期/赛季 | Click（仅接入 Schedule 时） | 左键单击 | Tab→Enter | 焦点/悬停高亮 | 进入日程界面 |
| 日期/赛季 | Read-only（未接入 Schedule） | 无 | 不进入 Tab | 无 | 仅显示时间信息 |
| 经费 | Read-only | 悬停可显示简短 tooltip | 不进入 Tab | 可选 tooltip | 信息展示，不导航 |
| 运动点数 | Read-only | 悬停可显示简短 tooltip | 不进入 Tab | 可选 tooltip | 信息展示，不导航 |
| 可用行动窗口 | Read-only | 无 | 不进入 Tab | 数值更新反馈 | 信息展示，不导航 |
| 下一场比赛 | Click（仅可进入时） | 左键单击 | Tab→Enter | 状态胶囊高亮 | 进入比赛中心 |
| 下一场比赛 | Read-only（不可进入时） | 悬停可看原因 | 不进入 Tab | 禁用原因文本或 tooltip | 不导航 |
| 菜单按钮 | Click / Open | 左键单击 | `Esc` / Tab→Enter / Space | 按钮高亮 | 打开暂停菜单 |

### Zone B — 中央小镇地图主体

| 组件 | 操作 | 鼠标 | 键盘 | 反馈 | 结果 |
|------|------|------|------|------|------|
| 地图主体画布 | 浏览 | 无关键操作 | 无关键操作 | 画面稳定可见 | 提供 home feel |
| 建筑轮廓层 | 被动观看 | 无 | 无 | 环境动画/状态变化 | 不触发导航 |
| 环境角色层 | 被动观看 | 无 | 无 | 环境动画 | 不触发导航 |
| 轻量状态提示 | 阅读 | 无 | 无 | 文案按状态切换 | 重复关键上下文 |

**MVP 明确不支持的交互**：
- 地图拖拽平移
- 地图缩放
- 点击建筑进入详情
- 点击角色进入详情
- 建设拖放
- 左侧快捷图标点击
- 从中央地图直接进入商店/任务/统计/通知

### Zone C — 底部导航

| 组件 | 操作 | 鼠标 | 键盘 | 反馈 | 结果 |
|------|------|------|------|------|------|
| 球员入口 | Click | 左键 | `R` / Tab→Enter | 按钮高亮、选中态 | 进入球员管理 |
| 比赛入口 | Click（可用时） | 左键 | `M` / Tab→Enter | 按钮高亮、可用态变化 | 进入比赛中心 |
| 比赛入口 | Disabled（不可用时） | 悬停可看原因 | Tab 跳过 | 禁用样式 + 原因说明 | 不执行导航 |

### Pause Menu Overlay

| 组件 | 键盘规则 | 结果 |
|------|----------|------|
| 暂停菜单 | `Tab/Shift+Tab` 循环，`Enter` 确认，`Esc` 关闭 | 不离开小镇主视图上下文 |

## Transitions & Motion

| 过渡 | 动画 | 时长 | 说明 |
|------|------|------|------|
| 主菜单 → 主视图 | 简洁淡入 | 500ms | 建立稳定的回归感 |
| L2 子界面 → 主视图 | 轻量返回过渡 | 200–250ms | 返回后立即可扫描 HUD |
| 主视图 → 球员/比赛 | 轻量进入过渡 | 200–250ms | 与 HUD 导航保持一致 |
| 比赛可进入状态变化 | 单次轻量强调 | 200ms | 顶部与底部同步更新 |
| 资源数值变化 | 轻量更新 | 200ms | 只作用于对应字段 |
| Toast 出现 | 淡入/淡出或即时显示 | 50–200ms | 不抢焦点，不打断导航 |

**Reduced-motion**：所有动画退化为 50ms 淡入淡出或静态高亮；比赛提醒不使用循环脉冲。

## Accessibility

无障碍层级：**WCAG-AA**。

### 1. 最低执行要求

- 所有正式交互元素支持键盘访问。
- 所有禁用态必须说明原因，不能只靠颜色表达。
- 比赛可开始、资源预警等状态必须使用颜色 + 图标/文字双通道。
- 正文最小字号 12px；720p 下 HUD 关键标签可读。
- 所有强调动画提供 reduced-motion 静态替代。
- 核心流程不得依赖中央地图的鼠标热点操作。

### 2. Focus Order

默认 Tab 焦点顺序：

1. 日期/赛季（仅当 Schedule 已接入且可点击时）
2. 下一场比赛状态（仅当可点击时）
3. 菜单按钮
4. 球员入口
5. 比赛入口（仅当可用时）

不进入 Tab 顺序的元素：
- 经费
- 运动点数
- 可用行动窗口
- 中央地图主体
- 建筑轮廓层
- 环境角色层
- 只读状态提示

### 3. Screen Reader / AccessKit Risk

若 Godot 4.6 AccessKit 路径已验证可用，则本界面最少实现：
- 菜单、球员、比赛的稳定可播报名称
- 日期、经费、运动点数、行动窗口、下一场比赛的可读取文本
- 打开暂停菜单时播报菜单标题
- 比赛入口从禁用变为可用时发送一次非侵入式状态播报

若 MVP 阶段尚未验证，则不得宣称已完成完整屏幕阅读器支持，并沿用风险记录：`HUD-A11Y-R1 Screen reader support not yet verified in engine build`。

### 4. Central Map Accessibility Rule

中央地图主体在 MVP 中不是关键输入层，因此不会成为键盘玩家的阻塞点。若未来版本要给地图加入可交互热点，必须另行补充键盘等效路径与新的焦点顺序后，才可进入 MVP 承诺。

## Acceptance Criteria

- [ ] 非比赛全屏场景中，小镇主视图只使用 **顶部状态栏 + 中央地图主体 + 底部导航** 的严格 MVP 结构。
- [ ] 常驻 HUD 元素仅包含：日期/赛季、经费、运动点数、可用行动窗口、下一场比赛状态、菜单、球员入口、比赛入口。
- [ ] 文档与实现中不包含左侧快捷栏、五标签底栏、ticker/info bar、通知中心入口、统计面板入口、常驻声望、常驻建设入口、常驻商店入口、常驻任务入口、研究点数显示。
- [ ] 中央区域保留小镇/home feel 与中央地图主体，但不承诺地图拖拽、缩放、建筑点击、角色点击、建设拖放等 MVP 交互。
- [ ] 球员入口始终可通过鼠标与键盘访问；当球员数为 0 时，仍可进入球员界面的空状态。
- [ ] 比赛入口仅在上游条件允许时可用；不可用时显示明确原因，且不会表现为可点击状态。
- [ ] `match_trigger_reached = true` 且比赛中心可进入后，顶部“下一场比赛”与底部“比赛”入口应在 250ms 内或下一次渲染周期内同步更新为可进入状态；reduced-motion 下仅使用静态高亮。
- [ ] 当 `Schedule` 尚未接入 MVP 时，日期元素保持只读，不伪装为可点击入口。
- [ ] 当单一数据源加载缓慢或失败时，仅对应 HUD 元素进入加载态/错误态；其余元素与中央地图主体继续可见，界面不得整体消失。
- [ ] Tab 遍历只停留在正式可交互元素上；只读统计项与中央地图主体元素不进入焦点顺序；禁用比赛按钮跳过焦点。
- [ ] 暂停菜单打开后形成焦点陷阱；关闭后焦点返回菜单按钮。
- [ ] Match Pre / Match Live / Match Result 三个阶段由比赛表现 UI 全屏接管；HUD 与小镇主视图完整隐藏。
- [ ] 若非 MVP 系统在原型中仍有残留占位，它们必须默认隐藏、无默认快捷键、无教程绑定，且不写入 MVP 承诺。
