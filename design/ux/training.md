## Purpose & Player Need

### 目的

训练界面是玩家执行 **"投入训练 → 看到成长"** 核心循环的主阵地。它的设计目的是：

1. **支撑清晰、有信心的决策**
   让玩家在训练前能快速判断：该练谁、练什么、投入多少资源，从而减少"怕练错"的焦虑。

2. **放大成长的获得感**
   训练结果不仅要显示"涨了数值"，更要让玩家感受到培养的回报——无论是属性爆发、短板补齐，还是角色适应性提升。

3. **建立长期培养的叙事感**
   通过成长轨迹回顾，让玩家看到自己的培养决策如何一步步塑造球员，形成"我懂他，我塑造了他"的情感绑定。

### 玩家需要回答的核心问题

| 阶段 | 问题 |
|------|------|
| 训练前 | 我这批球员里，谁最适合练这个项目？这个项目对改善他的短板/发挥他的潜力有多大帮助？这次训练会消耗什么（经费/AP/时间）？值不值？ |
| 训练后 | 涨了哪些属性？涨了多少？谁涨得最好？这次结果是正常发挥、惊喜爆发，还是没达到预期？这个成长对我的下一场比赛有什么影响？ |
| 长期回顾 | 我最近几周的训练方向对吗？球员在持续进步吗？他离我理想的角色模板还差多少？ |

### 用户故事

- **US-TRAIN-01**: 我作为经理，在安排每日训练前，能快速看到每个球员当前关键属性 vs 潜力上限的差距，以及该球员与不同训练项目的匹配度，以便我把有限的训练资源投给最需要且最适合的人。
- **US-TRAIN-02**: 我作为经理，在选择一个训练项目时，系统会明确提示该项目的主要成长属性、次要成长属性以及可能影响的战术角色，避免我靠猜测做决策。
- **US-TRAIN-03**: 我作为经理，在训练结束后，能一眼看到哪个球员涨了多少（尤其突出 +2 及以上的关键属性），并知道这次成长是否触发了"爆发成长"或"收益递减"，以判断这次训练是否超值。
- **US-TRAIN-04**: 我作为经理，可以查看某个球员的训练历史卡片（近5～10次训练的成长轨迹），了解他是在匀速进步、突然爆发还是陷入瓶颈，从而决定是否调整训练策略。
- **US-TRAIN-05**: 我作为经理，在训练结算时，希望看到成长结果与该球员当前角色要求的对比（例如"你的抢断从 12 → 13，离全能中场要求的 14 更近了"），帮助我把微观成长联系到宏观战术目标。

## Player Context on Arrival

| 到达场景 | 情绪状态 | 设计含义 |
|----------|----------|----------|
| 从球员详情「培养」按钮进入 | 聚焦、有目的——已选定球员，准备决定练什么 | 训练项目选择界面默认展示该球员信息；项目列表突出匹配度排序 |
| 从 HUD 主内容区的训练入口进入 | 浏览、比较中——尚未决定练谁，需要全局判断 | 默认展示可训练球员列表（按训练价值排序），支持横向比较后再选项目 |
| 训练结算后自动进入成长回顾 | 期待、好奇——"这次练得怎么样？" | 成长变化应醒目呈现（属性涨跌高亮），避免被其他信息淹没 |
| 比赛后针对性训练 | 有动机——比赛暴露短板，想立刻补强 | 若从赛后入口进入，可提示"比赛表现最差的 3 名球员"或"本场失误相关属性" |
| 新档首次打开 | 好奇但陌生——不知道训练能做什么 | 引导提示标注核心操作："选择球员 → 选择项目 → 确认训练"；空状态下首个训练有额外引导 |

## Navigation Position

训练界面有两条主要到达路径，均需与当前 HUD / 主循环壳层保持一致：

```
主菜单 (L0) → 小镇主视图 / Home (L1) → Training 主内容视图 (L2)
主菜单 (L0) → 小镇主视图 / Home (L1) → 球员界面 (L2) → 球员详情 (L3) → 训练安排 (L3)
```

说明：
- Training 属于 HUD 主内容区切换出的主循环视图，不依赖旧侧边栏或额外常驻导航栏。
- 由球员详情进入时，训练界面以当前工作区内替换/覆盖方式呈现，不再额外增加导航深度。
- 无论从哪条路径进入，顶部状态栏与底部 HUD 导航保持当前壳层规则；训练界面只负责自身内容区。

|----------|----------|------|

## Layout Specification

### Information Hierarchy

**视图 A: 训练规划 (Training Planning)**

| 层级 | 包含信息 | 设计理由 |
|:---:|------|------|
| **L1** 一眼可见 | ① 球员摘要 + ② 可用行动窗口数 + ③ 训练项目列表 | 玩家进入后立刻知道"我在练谁、能练几次、有哪些选项" |
| **L2** 主动浏览 | ④ 五维雷达（当前值+潜力上限双线） + ⑤ 训练效率标签 | 决策辅助——决定"选哪个项目"时的参考依据 |
| **L3** 按需操作 | ⑥ 消耗汇总 + ⑦ 预估收益 + ⑧ 开始训练按钮 + ⑨ 切换球员 | 选定项目后才需要看消耗/收益，确认后执行或切换 |

**关键逻辑**: L1 不需要雷达和效率标签。玩家进入训练界面的第一秒，最需要知道"我在练谁、能练几次、练什么"。L2 是决策辅助——雷达图显示成长空间，效率标签提示"现在练值不值"。L3 是确认层——消耗和预估收益只在选中具体项目后才有意义，开始按钮在选中项目后才激活。

**视图 B: 成长回顾 (Growth Review)**

Growth Review 在 MVP 中不是占位页，而是训练完成后的必经结果视图。它必须让玩家在 3–5 秒内回答四个问题：
1. 这次训练练了谁、练了什么。
2. 实际涨了哪些属性、哪些没有变化。
3. 这次结果属于爆发、正常还是低收益。
4. 接下来最自然的下一步是什么（继续训练下一位 / 返回当前球员）。

**MVP 最低实现边界**：
- 必须包含明确的结果头部、属性变化列表、训练结果解释、下一步操作区。
- 必须支持键盘完整操作，不依赖 hover 才能理解结果。
- 必须与 Training Planning 共享同一训练壳层信息锚点（当前球员、AP 余量），但不要求补齐 Alpha 版的长期分析深度。
- 可暂不做完整“历史深挖面板”或复杂多层 drill-down，但不可只停留在 wireframe 占位描述。

## States & Variants

训练界面包含三个核心子视图，对应 GDD 中的训练流程状态：Training Planning → Growth Review → Development Milestone。

| 状态 | 触发 | 变化 |
|------|------|------|
| **Default (Training Planning)** | 正常进入，有可训练球员 + 有可用行动窗口 | 如 ASCII Wireframe 所示——顶部球员栏 + 左雷达 + 右项目列表 |
| **Project Selected** | 玩家点击一个训练项目行 | 项目行高亮边框；底部预览面板从下方滑入（消耗 + 预估收益 + 开始按钮） |
| **Growth Review** | 训练结算完成 | 主区域替换为成长结果面板：顶部结果栏 + 属性变化列表 + 结果解释 + 角色对比（若适用）+ 下一步操作；左侧雷达同步为训练后状态（见下方 Growth Review Wireframe） |
| **Development Milestone** | 球员跨过关键阈值（如综合评分突破 80、潜力兑现 > 90%） | Growth Review 顶部或左栏插入里程碑卡片（金色边框 + 粒子效果）：显示里程碑名称、触发条件、对球员定位的影响；里程碑卡片 3s 后自动消失，或点击关闭；不阻塞 Growth Review 结果查看 |
| **Empty** | 球队无球员 | 项目列表区替换为引导文案：「还没有球员——去招募你的第一名球员吧」+ 招募快捷入口 |
| **All Exhausted** | 可用行动窗口 = 0 | 训练项目列表全部灰掉（禁用态 50% 透明度）；顶部提示：「今日行动次数已用完——推进时间到下一阶段」 |
| **At Cap** | 球员在当前项目主属性上已达潜力上限 | 该项目行显示 🔒 锁图标 + 「已达上限」标签；预估收益区显示「该属性无法继续成长」；开始按钮禁用 |
| **Low Efficiency** | 球员 `fatigue_adjusted_training_efficiency` < 0.7 | 效率标签变黄/红 + 警告图标；预估收益显著降低；内联文案解释主要原因（疲劳/伤病/心情），而不是只依赖 tooltip |
| **Error** | 训练结算失败（例如资源不足、训练数据不可用） | 当前训练选择保留；预览面板替换为错误提示：「训练失败 — {原因}」+ [重试] 和 [取消] 按钮；资源显示保持训练前状态；[取消] 返回项目选中状态 |
| **Loading** | 数据加载中 | 项目列表区骨架屏（灰色占位行 × 3）；雷达图灰圈；球员摘要骨架 |

### Growth Review Layout Zones

采用与 Training Planning 一致的双栏结构，避免玩家在结果页重新学习布局。

| 区域 | 位置 | MVP 内容 | UX 目的 |
|------|------|----------|---------|
| 顶部结果栏 | 顶部 64px | 返回按钮、球员摘要、训练评价标签、更新后的 AP 余量 | 提供身份锚点与结果定性，帮助玩家立即确认“谁发生了什么” |

### Growth Review 的关键交互

| # | 交互 | 细节 |
|---|------|------|
| 1 | 首屏结论优先 | 进入 Growth Review 后，玩家无需滚动即可同时看到训练评价、至少 3 行属性结果和一个下一步按钮 |
| 2 | 属性变化动画 | 新值闪烁 3 次（500ms 周期）；+2 以上标绿色 + 上箭，+0 标灰色 →，无变化保持原色；reduced-motion 下改为静态高亮 |
| 3 | 效率评价 | >1.3→「爆发成长！」金色，1.0-1.3→「出色」绿色，0.7-1.0→「正常」白色，<0.7→「收效甚微」黄色；同时显示文字，避免只靠颜色 |
| 4 | 结果解释 | 用 1 句话总结本次收益原因，例如「设施加成与良好状态带来了高于平均的主属性成长」；不要求暴露底层结算写路径 |
| 5 | 角色对比 | 显示主属性离下一角色要求的差距变化；若项目未接入明确角色目标，则整块隐藏，不显示占位文案 |
| 6 | 训练下一位 | 自动切换到训练价值排序中的下一位球员，回到 Training Planning 状态；训练项目选择重置（不保留上一球员的项目选中态）；需重新选择项目并确认 |
| 7 | 返回与历史 | `返回球员详情` 保留当前结果已读语境；`查看历史` 为次级操作，不抢占默认焦点 |
| 8 | 里程碑叠加 | 若触发 Development Milestone，在属性变化区上方插入里程碑卡片；3s 后自动淡出，或允许手动关闭，但不遮挡主操作按钮 |

### Implementation Readiness Notes

当前训练界面所依赖的训练项目数据源已存在于：
- `assets/data/training-items.csv`

因此，训练项目列表、主/副属性标签、资源消耗、匹配度字段不再属于“缺文件导致无法实现”的阻塞项。

但在进入 UI 实装前，仍需确认以下实现就绪性条件：

1. **唯一权威数据源**
   - 需确认训练项目数据是否以 `assets/data/training-items.csv` 为唯一权威源，
   - 或是否还存在并行的 config/resource 数据副本。
   - 若存在双源，必须在实现前先统一口径，避免 UI 显示与训练结算逻辑读取的来源不一致。

2. **ConfigLoader / 运行时接入方式**
   - 需确认运行时是直接消费该 CSV，还是通过 `ConfigLoader` / 预处理资源加载。
   - 本 UX spec 只要求玩家可见字段完整、一致、可解释，不规定具体装载技术路径。

3. **字段完整性验证**
   - 至少应验证每个训练项目具备：项目名、主属性、副属性、资源消耗、匹配度相关字段。
   - 若部分字段缺失，Training Planning 必须降级为可解释占位，而不是静默留空。

结论：当前训练界面已具备“数据文件存在”的实现前提；剩余风险不在 UX 结构，而在数据接入口径确认。

## Accessibility

无障碍层级：**WCAG-AA**（已正式承诺，详见 `design/accessibility-requirements.md`）。此界面满足：

- **键盘导航 Tab 焦点顺序**: 返回 → 球员摘要 → 切换球员 ← → → 雷达图（逐轴 Tab）→ 项目标签栏（1-5）→ 项目列表行（↑↓ 选择）→ 开始训练按钮
- **列表导航**: ↑↓ 选择训练项目行，Enter 选中/确认，ESC 取消选中/返回
- **雷达图**: 每轴有文字标签（SPD/PWR/TEC/INT/STA），不单独依赖颜色/形状区分 — 配合 #21 Color-Blind Friendly
- **匹配度星级**: 星级 + 数字匹配度百分比双重编码 — 不单独依赖颜色
- **训练效率**: 图标 (↑/→/↓) + 文字等级 + 颜色三重编码
- **属性变化**: 绿色高亮 + ↑/→ 箭头 + 数值差值三重编码
- **禁用态**: 不可用按钮/项目行 50% 透明度 + `aria-disabled` 语义标记
- **确认对话框**: 训练执行前弹出资源消耗确认（#9 Light Confirmation），包含经费/AP/时间窗口摘要和不可逆提示；确认后执行训练结算
- **Reduced-motion**: 所有过渡动画缩短为 50ms 淡入淡出；属性闪烁改为静态高亮；里程碑粒子取消

无障碍层级 WCAG-AA 已正式承诺（`design/accessibility-requirements.md`），本界面满足 §8 Per-Screen Checklist 全部适用项。

## Acceptance Criteria

- [ ] 训练界面从球员详情「培养」按钮点击后，在 300ms 内完成滑入并展示该球员的摘要、雷达图和项目列表
- [ ] 从 HUD 主内容区进入 Training 时，默认展示训练价值最高的球员；球员摘要、雷达图和项目列表在 500ms 内就绪
- [ ] 点击训练项目行 → 高亮边框 + 底部预览面板 150ms 滑入，显示消耗汇总 + 预估收益；取消选中 → 预览面板 120ms 滑出
- [ ] 选中项目后点击「开始训练」→ 弹出确认对话框（含资源消耗摘要和不可逆警告）→ 确认后执行训练结算 → Growth Review 覆盖层 300ms 淡入
- [ ] Growth Review 首屏无需滚动即可同时显示：训练评价、至少 3 行属性变化、资源消耗摘要，以及至少 1 个明确下一步按钮
- [ ] Growth Review 正确显示：属性涨跌高亮（+2 以上绿色闪烁 + 箭）、效率评价标签、结果解释文案、角色对比提示（若有位置定位）
- [ ] Growth Review 在无角色定位数据时隐藏角色对比模块，不显示空白占位或报错文本
- [ ] Growth Review 的默认焦点落在推荐下一步动作（推荐为「训练下一位」；若无下一位可训球员则落在「返回球员详情」）
- [ ] 空状态：球队无球员时，项目列表区替换为引导文案 + 招募快捷入口
- [ ] All Exhausted 状态：可用行动窗口 = 0 时，所有项目行灰掉（50% 透明度），顶部提示「今日行动次数已用完」
- [ ] At Cap 状态：球员在主属性上已达潜力上限时，该项目行显示 🔒 锁图标 + 「已达上限」标签，开始按钮禁用
- [ ] Tab 焦点顺序符合键盘导航路径：返回 → 球员摘要 → 切换球员 → 雷达图 → 项目标签 → 项目列表 → 开始训练；↑↓ 可选择项目行，Enter 选中，ESC 取消/返回
- [ ] Growth Review 中，Tab 顺序只停留在可交互元素（查看历史/训练下一位/返回）；属性变化列表可通过方向键或逐项聚焦读取，不要求鼠标悬停
- [ ] 训练效率标签使用图标 (↑/→/↓) + 文字等级 + 颜色三重编码——红色盲模式下仍能通过图标和文字区分
- [ ] 从 Player Detail 的「培养」入口进入训练时，训练界面显示的是该球员信息，而非默认第一位球员
- [ ] Growth Review 正确显示属性变化：+2 以上主属性绿色闪烁（500ms × 3）+ ↑ 箭头，+0 灰色 →，无变化保持原色
- [ ] Growth Review 效率评价标签与公式输出一致：>1.3→「爆发成长！」金色，1.0-1.3→「出色」绿色，0.7-1.0→「正常」白色，<0.7→「收效甚微」黄色
- [ ] Growth Review 中点击「训练下一位」自动切换到训练价值排序下一位球员并回到 Training Planning（项目选中态重置）
- [ ] 训练结算失败时显示错误提示（含原因+重试+取消），资源值回到训练前可感知状态，且玩家不会看到“已消耗但无结果”的矛盾反馈
